# 병원 이동 보조 자율 휠체어

> 현재 기획의 우선 기준은 [프로젝트 큰 틀 기준선](docs/product/big-picture.md)이다. 아래 세부 정책과 다른 운영 문서는 팀 합의 전 브레인스토밍 초안이며 구현 지시가 아니다.

병원 관계자의 예약 이동과 환자의 현장 호출을 실제 축소형 자율주행 휠체어의 운행으로 연결하는 종단 시스템 POC다.

대회에서는 영유아보다 조금 작은 인형이 탑승하는 한 대의 축소형 휠체어를 사용한다. 실제 사람을 태우거나 의료기기 수준의 안전성을 검증했다고 주장하지 않는다.

## 현재 기획 기준선

- 의료진 예약과 환자 직접 호출은 두 요청 진입점이다. 미시작 요청이 충돌하면 의료진 예약을 기본 우선 처리하고, 의료진은 필요하면 순서를 바꿀 수 있다. 이미 탑승해 이동 중인 환자는 중단하지 않는다.
- 의료진 예약의 시간은 환자의 목적지 도착 목표시각이다.
- 의료진 예약과 환자 직접 호출은 모두 스스로 승하차할 수 있는 비응급 환자를 대상으로 한다.
- 실제 서비스에서는 환자 개인 스마트폰 웹을 사용하고, 대회 MVP에서는 승차장 태블릿·키오스크 화면을 사용한다.
- 사용 중인 휠체어에 새 요청이 들어오면 대기열에 등록하고 대기 순번과 예상 대기시간을 표시한다.
- 환자는 QR 탑승 확인 전까지 자신의 요청을 취소할 수 있다.
- 의료진도 탑승 확인 전까지 자신이 만든 예약을 취소할 수 있으며, 이동 중인 빈 휠체어는 다음 요청으로 재배정하거나 대기 위치로 복귀한다.
- 빈 휠체어는 대기 위치에서 승차 지점으로 이동한 뒤 현장 확인을 기다린다.
- 대회 MVP에서는 고정된 모형 QR로 탑승 대상과 미션 확인 흐름을 보여준다.
- 의료진 예약의 환자가 없으면 의료진에게 보고한 뒤 자동 복귀한다.
- 승차장 직접 호출의 환자가 없으면 기본 3분 대기·소리 알림 후 자동 복귀한다. 대회 시연에서는 10초로 축약한다.
- 목적지 도착 목표시각 지연이 예상되면 의료진에게 알리고 운행은 계속한다.
- 로봇은 사전에 주어진 병원 지도를 기준으로 승차 지점과 목적지 사이를 이동한다.
- 관제 화면에는 정밀 좌표보다 미션, 목적지, 의미적 위치, 진행 상태와 정지 이유를 표시한다.
- 장애물을 감지하면 먼저 정지하고, 주어진 지도 안에서 대체 경로 선택 또는 제한적인 현재 경로 수정 가능성을 판단한다.
- 움직이는 사람도 장애물 상황으로 처리하며 먼저 정지한 뒤 상황에 맞는 대응을 판단한다.
- 안전한 이동 방법을 찾지 못하면 움직이지 않고 운영자에게 상태를 알린다.
- 목적지 운행이 끝난 빈 휠체어는 대기 위치로 자동 복귀한다.
- 하차 완료는 센서 자동 확인을 우선하고, 불확실하면 환자 버튼, 필요하면 의료진 확인을 사용한다.
- 승객 운행 중 `정지·도움 요청`이 들어오면 즉시 정지하고 현장 알림음과 화면 표시로 알리며 등록된 담당 의료진·담당 병동 알림 대상에게 통보한다. 의료진 확인 전에는 자동 재출발하지 않는다.
- 환자 화면에는 배정·예상 도착시간·운행 상태·취소·도움 요청과 병원 지도의 예정 경로·의미적 위치를 함께 표시한다.
- 실제 서비스에서는 예약 환자의 병원 팔찌·환자 QR과 직접 호출 환자의 앱 QR을 구분해 사용한다.
- QR이 미션과 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.
- 빈 휠체어가 승차 지점으로 이동 중 요청이 취소되면 다음 요청에 재배정하고, 없으면 대기 위치로 복귀한다.
- 새 출발 전 배터리를 확인하고, 운행 중 일반 저전력이 확인되면 현재 승객 운행을 마친 뒤 복귀한다.
- 즉시 운행을 계속할 수 없는 임계 전원 문제는 일반 저전력과 구분해 안전정지한다.
- 미지 환경의 범용 자율주행, 실제 EMR 연동과 복수 차량은 대회 MVP에서 제외한다.
- 청소·충전·정비 운영 관리는 대회 MVP에서 제외하고, 출발 전 배터리 운행 가능 여부만 확인한다.
- 대회 시연은 환자 직접 호출을 중심으로 하고 의료진 예약 흐름은 보조적으로 보여준다.

## 저장소 영역

- `docs/`: 기획, 설계, 안전, 조사 및 대회 문서
- `clients/web/`: 환자 스마트폰 웹, 대회용 승차장 태블릿·키오스크와 의료진 화면 후보 영역
- `server/`: 목적지 도착 목표시각 예약, 직접 호출, 대기열·예상 대기시간, 배차 및 운행 이력
- `robot/`: 별도 상위 제어 보드를 사용할 경우의 경로 실행·인지·안전 소프트웨어
- `firmware/`: 모터, 센서, 통신과 저수준 안전 제어 후보 영역
- `hardware/`: 기구, 회로, 전원, 물리 비상정지, 부품 및 조립 자료
- `contracts/`: 최소한의 API, 로봇 통신 및 경로 규격
- `data/`: 지도·경로 후보 데이터, 가상 데이터와 시험 결과
- `simulation/fake-robot/`: 하드웨어 없이 종단 흐름을 확인하기 위한 후보 영역
- `tests/`: 계약, 통합, 종단 및 실차 시스템 시험
- `demo/`: 대회 시연 시나리오와 증거 자료

## 상태

현재는 프로젝트의 큰 틀과 팀 합의 항목을 정리하는 단계다. 운영 예외, 지도 표현, 위치 추정, 경로 계산 알고리즘, 센서, 제어 보드와 안전 임계값은 아직 확정하지 않았다. 미결정 사항은 `docs/product/open-questions.md`에서 관리한다.
