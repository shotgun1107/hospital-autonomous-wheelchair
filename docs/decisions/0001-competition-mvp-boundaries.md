# ADR-0001: 대회 MVP 경계

- 상태: 채택
- 날짜: 2026-08-08

## 배경

한 대의 축소형 자율주행 휠체어, 두 요청 흐름, 웹·서버·로봇·펌웨어·하드웨어와 자율주행 기능을 모두 넓게 구현하면 제출 마감 전 종단 안정화를 보장하기 어렵다. WHILL과 기존 대회 작품 때문에 자율주행 휠체어라는 주제 자체의 최초성도 주장할 수 없다.

## 결정

- 작품 정체성은 예약·직접 호출을 물리 운행과 연결한 축소형 자율주행 휠체어 종단 POC로 유지한다.
- 의료진 예약과 환자 직접 호출을 동일한 미션 흐름의 두 진입점으로 둔다.
- 의료진 예약은 목적지 도착 목표시각을 입력한다. 미시작 요청이 충돌하면 의료진 예약을 기본 우선 처리하고 의료진은 필요하면 순서를 바꿀 수 있으며, 이미 탑승해 이동 중인 환자는 중단하지 않는다.
- 사용 중 새 요청은 대기열, 대기 순번과 예상 대기시간을 제공하고 환자의 미시작 대기 취소를 허용하며, MVP 탑승 미션은 고정 모형 QR로 확인한다.
- 등록된 승차 지점, 사전에 주어진 병원 지도와 통제된 시연 공간을 사용한다.
- 장애물 감지 시 먼저 정지하고, 안전한 대체 이동 방법을 찾으면 같은 미션을 계속하는 기능을 범위에 둔다.
- 장애물 주변의 제한적 현재 경로 수정은 조건부 후보로 두며 구체적인 방법은 기술 설계에서 결정한다.
- 정밀 좌표 관제 대신 의미적 위치와 상태를 사용한다.
- 한 대의 로봇에는 활성 미션을 하나만 허용한다.
- 목적지 운행 후 빈 휠체어의 대기 위치 자동 복귀를 포함한다.
- 실제 서비스는 환자 개인 스마트폰 웹, 대회 MVP는 승차장 태블릿·키오스크를 사용하며 시연은 환자 직접 호출을 중심으로 한다.
- 두 요청 흐름의 대상은 스스로 승하차할 수 있는 비응급 환자이며, 의료진은 탑승 확인 전까지 자신이 만든 예약을 취소할 수 있다.
- 두 번째 목적지와 카메라 분류는 핵심 안정화 후에만 추가한다.
- 실제 사람 탑승, 의료기기 주장, 실제 EMR 연동, 복수 차량과 미지 환경의 범용 자율주행은 제외한다.

## 보류한 결정

- 목적지 도착 목표시각을 만족시키는 출발시각 산정 방식
- 예상 대기시간 산정 방식과 실제 병원 QR 연동의 세부 흐름
- 실제 경로 센서·마커 조합
- 지도 표현, 위치 추정과 대체 이동 계산 방식
- SBC+MCU 또는 단일 MCU 배치

## 결과

정상 운행뿐 아니라 E-stop, 장애물, 통신, 경로와 수동 회수까지 종단 상태와 로그를 검증해야 한다. 기능 수보다 반복 성공과 보고서·영상 증거를 우선한다.

호출·예약·대기·탑승의 상세 제품 정책은 [ADR-0004](0004-service-policy.md)를 따른다.
환자 부재·지연·취소 정책은 [ADR-0005](0005-operational-exceptions.md)를 따른다.
하차 확인·빈 차량 재배정·배터리 정책은 [ADR-0006](0006-alighting-reassignment-and-battery.md)을 따른다.
도움 요청·화면 정보·QR 식별 정책은 [ADR-0007](0007-help-ui-and-identification.md)을 따른다.
이용 대상·의료진 취소·운영정보 노출 정책은 [ADR-0008](0008-eligibility-cancellation-and-visibility.md)을 따른다.
