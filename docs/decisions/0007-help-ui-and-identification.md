# ADR-0007: 도움 요청·화면 정보·QR 식별 정책

- 상태: 개인 기획 초안 · 팀 합의 전
- 날짜: 2026-08-08

> 도움 요청·화면·QR의 후보 정책을 보존한 문서이며 현재 구현 기준이 아니다. 큰 틀은 [프로젝트 큰 틀 기준선](../product/big-picture.md)을 따른다.

## 해결하려는 문제

환자가 운행 중 도움을 요청하는 상황, 대기 중 확인해야 할 정보, 의료진의 충돌 요청 화면과 실제 서비스의 환자 확인 방식을 상위 서비스 정책으로 정한다.

## 결정

- 승객 운행 중 환자가 `정지·도움 요청`을 누르면 휠체어는 즉시 정지한다.
- 현장에서는 알림음을 내고 화면에 도움 요청 상태를 표시하며 환자 정보에 등록된 담당 의료진 또는 담당 병동 알림 대상에게 알린다.
- 의료진이 상황을 확인하기 전에는 자동으로 다시 출발하지 않는다.
- 실제 서비스의 환자 화면에는 배정 여부, 예상 도착시간, 운행 상태, 탑승 확인 전 취소, 도움 요청, 병원 지도의 예정 경로와 휠체어의 의미적 위치를 함께 표시한다.
- 정밀한 실시간 좌표 표시는 필수로 요구하지 않는다.
- 대기 중에는 예상 대기시간과 대기 순번을 모두 표시한다.
- 의료진이 충돌 요청의 순서를 선택하는 목록에는 기본적으로 환자 ID와 목적지를 표시한다.
- 실제 서비스에서 의료진 예약 환자는 병원 팔찌·환자 QR을 사용하고, 환자 직접 호출은 앱 QR을 사용한다.
- 대회 MVP는 실제 병원 식별 체계와 연동하지 않고 고정된 모형 QR을 사용한다.
- 실제 서비스와 대회 MVP 모두 QR을 이용한 미션 확인 흐름을 유지한다.
- QR이 미션과 한 번이라도 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.
- 환자 부재 호출에는 단순 알림음과 화면 표시를 사용한다.

## 대회 MVP에서의 검증

- 가상 환자 데이터에 담당 의료진 ID를 두고, 실제 전화·문자·병원 호출망 대신 해당 의료진 웹 화면의 알림으로 통보 흐름을 검증한다.
- 병원 지도에는 정밀 좌표 대신 현재 구간 또는 등록 지점 같은 의미적 위치를 표시한다.
- 고정 모형 QR 불일치 시 목적지 운행 금지와 담당 의료진 웹 알림을 검증한다.

## 영향과 주의점

- 환자 화면에 상태와 지도를 함께 제공하므로 작은 화면에서 정보가 복잡해질 수 있으며, 실제 화면 구성은 이후에 정한다.
- 충돌 요청 목록을 환자 ID와 목적지만으로 단순화하면 의료진이 목적지 도착 목표시각을 비교하기 어려울 수 있다. 이 항목은 사용자 선택을 현재 기준으로 유지하되 화면 설계 검토 때 다시 확인한다.

## 이후에 결정할 세부사항

- 실제 병원에서 담당 의료진·담당 병동 알림 대상을 가져오는 시스템과 근무 교대 시 연결 방식
- 도움 요청을 받은 의료진의 확인·재개·회수 절차
- 알림음의 반복 횟수와 간격
- 병원 팔찌·환자 QR과 미션을 연결하는 실제 병원 시스템 연동 방식
- 의미적 위치의 화면 갱신 단위

위 항목의 세부 기술과 외부 시스템 연동은 현재 대회 MVP에서 확정하지 않는다.

## 장기 확장 아이디어

휠체어에 건강관리 모듈 또는 기존 환자 모니터링 시스템의 위급 신호를 연동하는 기능은 아이디어로만 남기고 대회 MVP에는 포함하지 않는다. 장기적으로 자동 위급 신호가 들어오면 즉시 정지하고 담당 의료진과 담당 병동 모두에 긴급 알림을 보내며 자동 재출발하지 않는 흐름을 검토한다. 실제 생체신호 측정과 위급 판단을 이번 결과물로 검증했다고 주장하지 않는다.
