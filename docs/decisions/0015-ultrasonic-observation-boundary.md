# ADR 0015: 초음파 거리 관측과 동적 Actor 추적의 경계

- 상태: 사용자 요청으로 문서 기준선에 반영, 하드웨어 세부 팀 확인 전
- 날짜: `2026-08-16`
- 범위: 축소 POC의 장애물 관측 연구와 하드웨어 연동 준비
- 비범위: 센서 모델·개수·배치 확정, 제품 알고리즘 채택, 실제 사람 안전 주장

## 배경

현재 동적 Actor 실험은 controller에 2차원 위치·속도·반지름을 가진 합성 `ActorTrack`을
제공한다. R2-B 감시 진입 보정도 Actor가 위험 구역에 들어오기 전에 이 추상 track을
확보할 수 있다는 상위 계약만 검증했다.

팀에서 전달된 최신 하드웨어 방향은 Arduino 계열 MCU와 초음파 거리 센서 사용이다. 다만
정확한 보드, 센서 모델, 개수, 장착 위치·방향, 측정 주기와 유효 거리는 아직 확인되지 않았다.
Arduino는 센서가 아니라 측정과 통신을 담당할 수 있는 MCU이므로 두 항목을 같은 사양으로
취급하지 않는다.

초음파 센서의 원시 출력은 일반적으로 특정 방향의 거리 관측이다. 단일 거리값만으로는
사람의 고유 식별자, 2차원 위치, 진행 방향과 속도를 직접 확정할 수 없다. 따라서 현재의
합성 `ActorTrack`을 초음파 센서가 곧바로 제공한다고 가정하면 증거 범위를 과장하게 된다.

## 결정

관측 계층을 다음처럼 분리한다.

```text
초음파 원시 거리 관측
→ source·시각·순서·유효성 검증
→ 센서별 거리·점유·접근 변화 증거
→ 필요한 정보가 충분할 때만 장애물 track 또는 보수적 점유 영역 생성
→ 기존 prediction·shared safety gate
```

다음 불변조건을 적용한다.

1. `no echo`, timeout, stale, 순서 역행과 출처 불일치는 빈 공간 증거가 아니다.
2. 센서 정보가 이동 허가에 필요한 수준보다 부족하면 새 비영점 이동을 허가하지 않는다.
3. 여러 반사체를 하나의 사람 track으로 임의 결합하지 않는다.
4. 센서 식별자, 측정 시각, 거리 또는 무응답, 상태, sequence와 장착 revision을 보존한다.
5. 초음파 측정과 현재 합성 `ActorTrack` 사이의 변환은 별도 검증 대상이다.
6. 장애물 소실 또는 정상 거리 한 번만으로 자동 재출발하지 않는다.
7. 실제 센서가 검증되기 전 R2-B 감시 진입 결과는 추상 상위 계약으로만 유지한다.

## 현재 선택하지 않는 것

- 특정 초음파 센서 모델
- 센서 개수와 전·후·좌·우 배치
- 거리 임계값, 빔 폭, 최대·최소 거리와 측정 주기
- 단일 센서 정지 전용과 다중 센서 추적 중 최종 MVP 방식
- Arduino와 상위 제어 보드 사이의 실제 메시지 형식
- 초음파만으로 사람·휠체어·벽을 분류할 수 있다는 주장

## 필요한 팀 입력

1. Arduino 보드와 초음파 센서의 정확한 모델명
2. 센서 수량과 차체 기준 장착 위치·방향·높이
3. 실제 측정 주기, 유효 거리, timeout과 무응답 표현
4. 여러 센서를 순차 구동할지와 상호 간섭 처리 방식
5. 펌웨어가 원시 거리만 보낼지, 필터된 거리·점유 상태도 보낼지
6. 대회 MVP가 정지 기능만 요구하는지, 움직이는 장애물 추적·우회까지 요구하는지

## 증거 경계

현재 Python의 Gaussian 위치·속도 관측, 방향성 Capsule과 감시 진입 world는 초음파 센서의
실측 성능을 증명하지 않는다. 이후 초음파 하네스도 축소 차체와 지정된 배치에서 측정한
범위까지만 주장하며 실제 사람 탑승 안전성이나 의료기기 적합성으로 확대하지 않는다.
