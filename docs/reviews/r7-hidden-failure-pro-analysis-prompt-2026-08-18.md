# Pro 분석 요청 — R7 비공개 관측 시험 실패 5건

## 역할

당신은 Python 이동 로봇 simulation의 상태 전이·재출발 권한·경로 구간 실행을 검토하는
수석 코드 리뷰어다. 첨부 ZIP의 결과와 코드를 읽고, 아직 코드를 수정하지 말고 원인과
수정 방향을 판정하라.

쉬운 표현을 우선하되, 코드 담당자가 바로 구현할 수 있도록 파일·함수·조건·시험 입력은
정확히 적어라.

## 지켜야 할 조건

- 충돌 여유, 관측 기준, stale 처리, 정지·재출발 권한과 평가 기준을 낮추지 않는다.
- 결과를 보고 episode 길이를 늘려 통과시키지 않는다.
- 비공개 case 이름이나 기대 결과를 controller 입력으로 넣지 않는다.
- 실패 입력은 이제 공개 회귀시험으로 사용할 수 있다.
- Python 로직을 먼저 바로잡는다. C++ 성능 코어 변경은 원인이 확인된 뒤 별도로 한다.
- 제품 알고리즘 채택, 실제 카메라와 사람 안전 결론을 내리지 않는다.

## 요청 결과 형식

### 1. 최종 판정

- 공통 원인이 있는지
- 각 실패가 코드 결함, 계약 충돌, 시험 기준 문제 중 무엇인지
- 수정 우선순위 `P0/P1/P2`

### 2. 사건별 시간 순서

각 5건에 대해 다음 상태가 언제 어떻게 바뀌었는지 결과 JSON과 코드로 역추적하라.

```text
관측 전달/누락
→ 안전정지 요청
→ 실제 정지 확인
→ stop_epoch 변경
→ 재출발 허가 생성
→ local window 갱신
→ active section 선택
→ controller 호출 또는 hold
```

확정할 수 없는 값은 추측이라고 표시하고, 추가해야 할 trace 필드를 적어라.

### 3. 코드 원인

각 원인마다 다음을 적어라.

- 정확한 파일·함수·조건
- 왜 공개 기본 seed에서는 통과했지만 이번 순서에서 깨지는지
- 안전하게 멈춘 정상 동작과 잘못 멈춘 상태 관리 오류의 구분
- 두 예외가 같은 상위 원인인지 별개 원인인지

### 4. 공개 재현시험

실패한 관측 seed를 이용해 최소 공개 재현시험을 설계하라.

- 먼저 추가할 시험 이름과 입력
- 코드 수정 전 반드시 실패해야 하는 조건
- 코드 수정 후 반드시 통과해야 하는 조건
- 충돌·권한·경로 구간·최종 완료를 각각 어떻게 확인할지
- 한 번 실행에 오래 걸리지 않도록 어느 tick까지 잘라 원인을 재현할지

### 5. 최소 수정안

- 코드 오류 2건을 먼저 막는 최소 수정
- Normal 미완료 2건의 진행 복구 수정
- Stress 무출발 위반 수정
- 수정이 기존 정상 case를 망가뜨릴 위험과 필요한 적대시험
- 단순 timeout 증가, 무조건 재출발, 예외 숨김 같은 잘못된 해결책을 명시

### 6. 구현 순서

최대 5단계로 정리하라. 각 단계마다 수정 파일과 실행할 표적 시험을 적어라. 전체 회귀는
마지막 한 번만 수행하도록 계획하라.
