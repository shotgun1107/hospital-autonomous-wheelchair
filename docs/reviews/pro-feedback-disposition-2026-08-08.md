# Pro 피드백 반영 판정

원문: `pro-feedback-2026-08-08.md`

## 반영 원칙

피드백을 그대로 요구사항으로 복사하지 않는다. 원래 사용자 의도, 대회 일정, 기술 위험과 하드웨어 미결정 상태를 기준으로 `채택`, `수정 채택`, `보류`, `기각`으로 나눴다.

## 채택

- 실제 환자가 아닌 인형을 사용하는 축소형 POC로 한정
- 지정된 승차 지점 사용
- 한 대의 로봇에 활성 미션 하나
- 의미적 위치·상태 관제와 로봇 내부 진행 판단의 분리
- 물리 E-stop, 장애물 보호정지, 통신·경로 상실 정지
- E-stop·근접 보호정지·통신·경로 상실 뒤의 자동 재출발 금지와 수동 회수 절차
- 반복 시험과 로그를 완성도 증거로 사용
- 실제 EMR, 복수 차량, 실환자 탑승과 정밀 좌표 관제를 MVP에서 제외

## 수정 채택

| 제안 | 반영 방식 |
| --- | --- |
| 단일 반응형 웹 | 실제 서비스는 환자 개인 스마트폰 웹, 대회 MVP는 승차장 태블릿·키오스크를 사용한다. 하나의 코드베이스로 만들지는 아직 결정하지 않는다. |
| 장애물 우회 제거 | 후속 사용자 결정으로 수정했다. 단순 정지만이 아니라 대체 이동 방법을 다시 찾는 기능 의도를 MVP에 복원한다. 지도 구조, 계산 알고리즘과 국소 수정 범위는 아직 확정하지 않는다. |
| 라인·체크포인트 | 사전에 주어진 지도와 통제 경로라는 상위 가정만 유지한다. 실제 경로 인식 방식은 기술 설계 전까지 채택하지 않는다. |
| 예약 목표시각 로직 | 목적지 도착 목표시각을 입력하는 서비스 정책은 채택했다. 실제 출발시각 산정 방식은 이후 설계로 미룬다. |
| 목적지 1개 | 첫 종단 통합 마일스톤에는 사용하지만 최종 시연 범위는 핵심 안정화 후 결정한다. |

## 보류

- `release_at = 목표 도착시각 - 이동시간 - 탑승 버퍼`의 최종 채택
- SBC+MCU 또는 단일 MCU 배치
- 경로·위치·장애물 인식의 구체적인 기술 조합
- 두 번째 목적지의 최종 시연 포함 여부

## 후속 사용자 결정으로 변경

- 자동 복귀는 후순위가 아니라 MVP 범위에 포함한다.
- 대회 시연은 환자 직접 호출을 중심으로 구성한다.
- 예약과 직접 호출이 충돌하면 의료진이 처리 순서를 선택한다.
- 사용 중 요청은 대기열과 예상 대기시간을 제공하고, 탑승 미션은 QR로 확인한다.

## 기각

- 인형을 제품의 실제 사용자로 정의하는 표현: 인형은 시험 대역이며 목표 사용자는 독립 승하차 가능한 환자다.
- 자율주행 휠체어를 단순한 예약 시스템의 부속 기능으로 축소하는 표현
- 한 개 목적지만으로 목적지 선택 기능을 완성했다고 주장하는 것
- Pro의 완성 가능성 백분율과 확신도를 확정 사실로 사용하는 것
- 장애물 대응을 보호정지와 수동 재개로만 제한하는 것: 자율주행 기술성과 원래 기획 의도를 위해 대체 이동 판단 기능을 유지한다. 구체 기술을 필수로 확정한 것은 아니다.

- 2026-09-03 제출 마감, 제출물과 평가 배점은 공식 자료로 확인된 사실이다.
- 9월 2일 내부 제출, 중간 기능 동결일과 5회 반복 기준은 위험관리를 위한 내부 권고다.
- 조기 등록은 공식 조기 마감이 아니라 제출 실패를 줄이기 위한 권고다.
