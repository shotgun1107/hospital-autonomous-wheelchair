## 2. 한 문장 소개

병원 관계자의 예약 이동과 환자의 직접 호출을 한 대의 축소형 자율주행 휠체어 운행으로 연결해, 거동이 불편하지만 스스로 승하차할 수 있는 비응급 환자의 원내 이동을 돕는 종단 시스템이다.

## 3. 짧은 소개문

병원에서는 검사실·진료실·병실 사이의 반복적인 환자 이동 때문에 의료진의 업무 부담이 커지고, 환자는 필요한 순간에 이동수단을 직접 확보하기 어렵다. 본 프로젝트는 의료진의 예약 요청과 환자의 직접 호출을 하나의 미션 체계로 통합하고, 빈 휠체어의 승차 지점 이동부터 탑승 확인, 목적지 운행, 장애물 대응과 자동 복귀까지 연결하는 축소형 자율주행 휠체어 POC다.

## 4. 해결하려는 문제

- 검사실·진료실·병실 이동에 반복적으로 투입되는 의료진의 환자 이송 부담
- 환자가 원하는 시점에 이동수단을 직접 요청하기 어려운 문제
- 호출·예약 시스템과 실제 이동 장치가 분리되어 발생하는 운행 상태 확인의 어려움
- 장애물, 통신 단절, 요청 취소와 도움 요청 같은 예외 상황을 안전하게 처리해야 하는 문제

## 5. 제안하는 해결 방식

### 의료진 예약 이동

의료진이 환자 식별정보, 승차 지점, 목적지와 도착 목표시각을 등록하면 시스템이 적절한 시점에 빈 휠체어를 승차 지점으로 보낸다.

### 환자 직접 호출

환자가 등록된 승차 지점의 태블릿·키오스크에서 목적지를 선택하면 빈 휠체어가 해당 위치로 이동한다. 실제 서비스에서는 환자 개인 스마트폰 웹으로 확장할 수 있다.

### 공통 종단 흐름

```text
예약 또는 직접 호출
→ 대기열·미션 생성
→ 빈 휠체어의 승차 지점 이동
→ QR 기반 탑승·미션 확인
→ 목적지 자율주행
→ 장애물·도움 요청 안전 처리
→ 하차 확인
→ 대기 위치 자동 복귀
```

## 6. 핵심 기능

- 의료진의 목적지 도착 목표시각 기반 예약
- 환자의 승차 지점 직접 호출과 목적지 선택
- 요청 대기열, 대기 순번과 예상 대기시간 표시
- 고정 모형 QR을 이용한 탑승 대상과 미션 확인
- 사전에 주어진 단층 병원 지도 기반 자율 이동
- 장애물 감지 시 로컬 안전정지와 대체 이동 가능성 판단
- 경로가 없거나 판단이 불충분할 때 `BLOCKED` 상태 유지와 운영자 알림
- 승객의 정지·도움 요청 시 즉시 정지 및 의료진 알림
- 통신·경로·전원 이상 시 보수적 정지
- 목적지 운행 종료 후 대기 위치 자동 복귀
- 미션 상태, 의미적 위치, 진행 상태와 정지 이유 표시
- 운행 사건과 반복 시험 결과 기록

## 7. 대회용 POC 범위

- 영유아보다 조금 작은 인형이 탑승하는 축소형 휠체어 한 대
- 실제로 움직이는 자율주행 하드웨어
- 사전에 지도가 주어진 통제된 단층 모형 병원
- 등록된 대기 위치, 승차 지점과 목적지
- 환자 직접 호출 중심의 종단 시연과 의료진 예약 보조 시연
- 실제 환자·성인은 탑승하지 않음
- 실제 EMR·HIS와 개인정보 대신 가상 환자 데이터 사용
- 복수 차량, 다층 이동과 미지 환경 범용 자율주행은 제외

## 8. 시스템 구성

```text
환자 태블릿·키오스크 / 의료진 웹
                ↓
요청·예약·대기열·미션 관리 서버
                ↓
ROS 2 기반 자율주행·경로 계획·상태 관리
                ↓
하드웨어 통신 게이트웨이와 프로토콜
                ↓
MCU 펌웨어·센서·모터·물리 안전장치
```

소프트웨어 영역은 프론트엔드, 서버, ROS 2, 자율주행 알고리즘, AI, 시뮬레이터와 하드웨어 통신 게이트웨이를 담당한다. 하드웨어 팀은 차체·회로·전원·센서·모터·MCU 펌웨어와 물리 E-stop을 담당한다.

## 9. 자율주행 연구 현황

Python `simulation_only` 경로 알고리즘 실험환경을 구축해 역할이 같은 후보를 동일 조건에서 비교하고 있다.

- 전역 경로 후보: Dijkstra, A*, D* Lite
- 로컬 경로 후보: Grid A*, DWA
- 경로 추종 후보: Pure Pursuit, RPP
- seed 기반 합성 지도, 독립 oracle, 결과 JSON·PNG와 회귀시험 환경 구현
- 현재 연구 기준 조합: `A* → Grid A* → Pure Pursuit`
- D* Lite, DWA와 RPP는 비교·개선 후보이며 제품 알고리즘으로 확정하지 않음

움직이는 원형 Actor 비교실험은 현재 1~5단계를 완료했다.

- 20 Hz open-loop 원형 Actor ground-truth 시뮬레이션
- 10 Hz 지연·noise·dropout 관측 생성
- stale·source·revision·hash 검증
- 관측 age와 운동 불확실성을 반영한 Actor prediction tube
- 문서 기록상 전용시험 43개, 1·2단계 영향권 53개, 전체 회귀 197개 통과

동적 safety gate, 제한 감속, 실제 정지 확인, `stop_epoch`, 재개 권한과 deadline 폐기까지
3단계로 구현했으며, 문서 기록상 3단계 전용시험 36개와 전체 회귀 233개가 통과했다.
PP·DWA 동적 adapter와 공통 safety gate를 20 Hz 폐루프로 연결한 4단계까지 구현했으며,
4단계 전용시험 16개와 당시 전체 회귀 249개가 통과했다. 이어 controller와 독립된
200 Hz ground-truth evaluator, golden 6개·development 30개와 fault catalog를 5단계로
구현했고, 5단계 전용시험 15개와 전체 회귀 264개가 통과했다. 전체 paired runner와
hidden·통계 판정은 아직 수행하지 않았다. 위 결과는 합성 Python 환경의 연구 증거이며
실제 센서나 사람 탑승 안전성의 증거가 아니다.

## 10. 차별점

자율주행 휠체어 자체의 최초성을 주장하지 않는다. 프로젝트의 차별점은 다음 기능을 하나의 실제 운행 흐름으로 연결하는 데 있다.

- 의료진의 예정 이동 등록과 환자의 직접 호출을 하나의 미션 체계로 통합
- 요청 화면에 그치지 않고 빈 차량 이동, 탑승 확인, 승객 이동과 자동 복귀까지 연결
- 장애물뿐 아니라 QR 불일치, 환자 부재, 요청 취소, 도움 요청과 통신 이상을 운행 상태로 관리
- 서버의 미션 권한과 로봇의 로컬 안전 권한을 분리
- 정상 동작뿐 아니라 안전정지와 실패 처리를 반복 가능한 시험 증거로 보존

## 11. 안전 원칙

- 장애물이나 판단 불충분 상태에서는 경로 변경보다 안전정지를 먼저 수행한다.
- 정지 요청과 실제 정지 완료를 구분한다.
- 위험 해소나 통신 복구만으로 자동 재출발하지 않는다.
- 최신 미션·지도·관측과 일치하지 않는 경로 결과를 실행하지 않는다.
- 서버 명령보다 로봇 로컬 안전 거부와 물리 안전장치를 우선한다.
- 실제 사람을 축소 POC에 태우지 않는다.
- 시뮬레이션과 축소 실물 결과를 의료기기 인증이나 실제 환자 안전성으로 확대하지 않는다.

### 현재 완료

- 안전 권한 흐름과 실패 조건 정리

- 동적 원형 Actor 실험 1단계 시뮬레이션 기반 구현
- 동적 원형 Actor 실험 2단계 관측·예측 구현
- 동적 원형 Actor 실험 3단계 safety gate·권한·시간 계약 구현
- 동적 원형 Actor 실험 4단계 PP·DWA 동적 closed-loop 구현

### 다음 연구 단계

1. 전체 paired runner와 manifest 동결
2. hidden 실험과 통계 기반 연구 기준선 판정
3. 팀 합의 후 ROS 2와 축소 하드웨어 종단 통합

최종 경로 전략, 실제 센서·차체 수치와 제품 알고리즘은 팀 검토 전 확정하지 않는다.

## 13. 기대 효과

- 의료진이 반복적인 원내 이동에 직접 동행하는 부담 감소
- 비응급 환자가 필요한 시점에 이동을 요청할 수 있는 선택권 확대
- 요청부터 실제 운행까지 상태를 일관되게 추적할 수 있는 운영 기반 마련
- 정상 주행뿐 아니라 실패와 안전정지를 포함한 재현 가능한 개발·검증 체계 확보

## 14. 신청서용 요약문

병원 이동 보조 자율 휠체어는 의료진의 예약 이동과 환자의 직접 호출을 하나의 미션 체계로 연결하는 축소형 종단 시스템 POC입니다. 환자 또는 의료진의 요청이 접수되면 빈 휠체어가 승차 지점으로 이동하고, QR로 탑승 대상과 미션을 확인한 뒤 사전에 주어진 병원 지도에 따라 목적지까지 주행합니다. 장애물이나 판단 불충분 상태에서는 우회보다 안전정지를 우선하며, 도움 요청·통신 이상·QR 불일치·환자 부재와 같은 예외 상황도 동일한 운행 상태로 관리합니다. 대회에서는 실제 사람 대신 인형을 태운 축소형 휠체어와 통제된 단층 테스트베드를 사용합니다. 현재 Python 기반 경로 알고리즘 비교환경과 동적 원형 Actor의 관측·예측, 공통 safety gate·정지·재개 권한 단계까지 구현했으며, 향후 PP·DWA 동적 폐루프 비교와 ROS 2·하드웨어 종단 통합을 진행할 계획입니다.
