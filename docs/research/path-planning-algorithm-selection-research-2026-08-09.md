## 이번 조사의 질문

다음 질문에 답하기 위해 로봇 내비게이션뿐 아니라 자동차, 창고·시설 로봇, 게임 AI, 도로 교통, 군중 이동, 선박 충돌 회피와 항공·산업 안전 구조까지 조사했다.

1. 알려진 병원 지도와 등록 지점 사이의 전체 경로는 무엇으로 선택할 것인가?
2. 기존 경로 주변의 제한된 공간만 수정하려면 무엇을 비교해야 하는가?
3. 움직이는 사람·카트·외부 휠체어에는 경로 수정, 기다림과 정지 중 무엇이 적절한가?
4. 축소형 대회 POC의 Python·Unity·실물 검증 비용을 감안하면 어떤 후보를 우선 비교해야 하는가?
5. 어떤 결과가 나오면 후보를 즉시 탈락시켜야 하는가?

이번 조사에서는 알고리즘, 센서, 좌표계, 미들웨어 또는 구현 언어를 최종 채택하지 않는다.

## 한눈에 보는 결론

### 1. 하나의 알고리즘을 고르는 문제가 아니다

경로 기능은 최소 다섯 책임으로 나뉜다.

```text
지도·경로 표현
→ 전체 경로 선택
→ 가까운 구간의 경로·궤적 수정
→ 계산된 경로 추종
→ 독립적인 이동 허용·정지 판단
```

- A*, Dijkstra, D* Lite는 주로 `전체 경로 선택` 계열이다.
- DWA/DWB, TEB, MPPI는 주로 `가까운 구간의 궤적 생성·수정` 계열이다.
- Pure Pursuit 계열은 주로 `이미 계산된 경로 추종` 계열이다.
- VO/ORCA와 SIPP는 `움직이는 대상과의 시간적 충돌`을 다루지만 요구하는 예측 정보가 서로 다르다.
- Collision Monitor, trajectory validator와 물리 비상정지는 planner 바깥의 `이동 허용·정지` 계층이다.

따라서 `A*와 DWA 중 무엇이 더 좋은가`라는 질문은 성립하지 않는다. 서로 다른 책임을 수행하므로 같은 계층 안에서 비교한 뒤 결합 정책을 별도로 비교해야 한다. [Nav2 공식 개념 문서](https://docs.nav2.org/concepts/)도 planner, controller, behavior와 safety 기능을 분리한다.

### 2. 조건이 충족될 때 비교 가능한 후보

아래 표는 최종 채택표나 확정된 비교 세트가 아니다. 아직 미정인 지도 표현, 허용 이탈 공간과 동적 대응 범위가 추후 승인될 경우에만 성립하는 **조건부 연구 후보표**다.

| 책임 | 연구 진입 조건 | 비교 가능한 후보 | 현재 연구 우선순위가 낮은 후보 |
|---|---|---|---|
| 전체 경로 선택 | 등록 통로 graph 표현을 승인하는 경우 | A*, 같은 정적 graph·비용의 Dijkstra 대조군, 반복적인 작은 통행 상태 변화가 있을 때 D* Lite | 원형 D*, HPA*, Contraction Hierarchies, JPS |
| 차체 수행 가능 경로 | 2D 경로를 실제 차체가 수행하지 못하는 경우 | State Lattice, 자동차형 운동 제약이면 Hybrid A* | 차체 제약을 모른 채 방향 포함 탐색을 먼저 고정하는 것 |
| 정적 장애물의 제한적 수정 | local 공간 표현과 이탈·재합류 범위를 승인하는 경우 | 제한 영역 A* 가설, DWA/DWB, TEB | 기본 APF 단독 채택, 원형 Elastic Band 단독 채택 |
| 현재 관측에 대한 local 반응 | 동적 대상을 피해 계속 움직이는 기능을 범위에 넣는 경우 | DWA/DWB, 기본 TEB, 일반 costmap 기반 MPPI | 갱신된 장애물 관측을 미래 사람 예측으로 간주하는 것 |
| 미래 동작을 사용한 충돌 판단 | 신뢰할 수 있는 개체 추적·속도·예측 입력을 제공하는 경우 | 동적 TEB 확장, 시간별 예측을 받는 MPPI, VO/ORCA | 사람 미래 궤적이 정확하다고 가정한 SIPP, 순수 Social-RL |
| 경로 추종 | 실제 차체와 제어 주기를 확인하는 경우 | 단순 waypoint 추종 또는 RPP | 추종기를 우회 planner라고 간주하는 것 |
| 이동 허가 | 모든 후보 공통 | 동일한 별도 정지·검증 규칙 | planner가 스스로 안전을 최종 승인하는 구조 |

`제한된 local grid의 A*`는 기존 제품이 정답이라고 확인된 방식이 아니라, 전역과 국소에서 같은 단순·결정론적 탐색 원리를 재사용할 수 있는지 확인하기 위한 프로젝트 전용 비교 가설이다.

### 3. 연구할 수 있는 최소 구성 가설 한 가지

다음은 현재 구조를 정하는 안이 아니라, 추후 각 진입 조건이 승인될 때 작은 실험으로 검증할 수 있는 구성 가설 한 가지다.

```text
graph 표현이 승인된 경우의 A*       : 다른 통로가 필요한 전체 경로 재선택 실험
local grid·이탈 범위가 승인된 경우  : 제한 영역 A* 우회·재합류 가설 실험
현재 승인된 정지 유지·재판단        : 예측하기 어려운 사람과 이동체
기다림 정책이 승인된 경우           : 일정 조건 뒤 재평가하는 별도 정책 실험
공통 추종기                         : 선택된 경로를 실제로 따라가는 역할
공통 안전 게이트                    : 불확실·오래된 입력·실패 시 정지 유지
```

이 가설은 비교 세트나 채택안이 아니다. 시연 지도에 갈림길이 없으면 graph A* 재선택 실험이 성립하지 않고, local 이탈 공간·차체 폭·회전 가능성이 없으면 local A* 가설도 성립하지 않는다. 동적 사람을 피해 계속 주행하는 기능을 추후 범위에 넣으면 DWA/DWB·TEB·MPPI 계열을 현재 관측 반응과 미래 예측 확장으로 나눠 비교해야 한다.

## 1. 지도 표현이 알고리즘보다 먼저인 이유

같은 A*라도 어떤 상태와 연결을 탐색하는지에 따라 결과가 완전히 달라진다.

| 표현 | 표현하는 것 | 장점 | 놓치기 쉬운 것 | 연결 의존성 |
|---|---|---|---|---|
| 등록 통로 graph | 승차장·목적지·교차점과 허용 통로 | 작고 설명 가능하며 통로 폐쇄를 edge 비활성화로 표현하기 쉽다. | 통로 안에서 장애물 주변을 어떻게 지나갈지는 모른다. | MAP-01/03/05/09, LOC-02 |
| 2D occupancy grid | 자유 공간·점유 공간 | 정적 장애물 주변의 기하학적 우회와 통과 가능성을 표현한다. | 방향, 회전반경과 실제 제동은 기본 상태에 없다. | MAP-02/04/08, OBS-02, VEH-01 |
| 방향 포함 grid/lattice | 위치, 방향과 허용 motion primitive | 차체가 실제 수행 가능한 회전·전후진을 탐색에 포함할 수 있다. | 지도·차체 제약과 계산량이 늘어난다. | MAP-02/04/08, VEH-01/02/04, SYS-06 |
| 시간 확장 graph | 위치와 도착 시간 또는 안전 시간 구간 | 예약된 다른 로봇처럼 미래 경로가 알려진 대상과 대기 행동을 표현한다. | 사람의 미래 경로가 틀리면 시간상 안전 판정도 틀린다. | OBS-03/04/06, SYS-07 |

[Nav2 Smac Planner](https://github.com/ros-navigation/navigation2/blob/main/nav2_smac_planner/README.md)는 같은 검색 framework 안에서도 원형 differential/omni 로봇의 2D A*, 자동차형 Hybrid-A*, 임의 motion primitive를 쓰는 State Lattice를 구분한다. 알고리즘 이름보다 상태 표현과 차체 가정이 먼저라는 직접적인 사례다.

## 2. 전체 경로 선택 후보

### 2.1 후보 비교

| 후보 | 핵심 성질 | 강점 | 실패·비용 | 현재 판정 |
|---|---|---|---|---|
| Dijkstra | 시작점부터 모든 방향으로 최단 비용을 확장 | 동일한 정적 graph와 비용 model 안에서 heuristic 없는 최단 비용 기준값을 만들 수 있다. | 목표 방향 정보가 없어 A*보다 불필요한 확장이 많고, 다른 표현·비용의 결과를 검산할 수는 없다. | graph 표현 승인 시 정답 대조군·oracle |
| A* | 현재 비용과 목표까지의 heuristic을 합쳐 탐색 | 작은 graph/grid에서 단순하고 결정론적이며 설명하기 쉽다. 표준 조건에서 최단 경로를 보존한다. | 장애물 변화 때 보통 다시 탐색하며, 상태가 2D면 차체 수행 가능성을 보장하지 않는다. | graph/grid 표현 승인 시 1차 비교 후보 |
| LPA* | 이전 탐색 결과를 재사용하는 증분 탐색 | 일부 edge 비용이 변할 때 재계산을 줄일 수 있다. | 이동하는 시작점까지 고려한 제품 흐름에는 D* Lite가 더 직접적이다. | 보류 |
| D* Lite | LPA* 계열을 이동 시작점과 변경 edge에 맞게 구성 | 같은 목적지로 이동하면서 일부 통로 비용이 반복 변경될 때 유리할 수 있다. | 작은 지도·드문 변경이면 A* 재실행보다 복잡성만 늘 수 있다. 사람의 움직임을 예측하지 않는다. | **조건부 비교 후보** |
| ARA* | 제한 시간 안에 suboptimal 해를 먼저 찾고 시간이 남으면 품질을 개선 | 큰 정적 상태 공간과 엄격한 계산 시간에서 anytime 성질이 있다. | 작은 축소 지도에서는 구현·검증 복잡성 대비 이득이 작을 가능성이 높다. | 조건부 보류 |
| AD* | anytime 개선과 변경된 edge 비용에 대한 증분 재탐색을 결합 | 큰 동적 상태 공간에서 빠른 첫 해와 이전 탐색 재사용을 함께 노릴 수 있다. | 현재는 D* Lite보다 복잡하며 작은 지도에서 추가 이득이 확인되지 않았다. | 조건부 보류 |
| Theta* | grid에서 격자 방향에 묶이지 않는 any-angle 경로 | 계단 모양 경로를 줄일 수 있다. | 차체 운동·회전·clearance를 자동 보장하지 않는다. | 경로 모양 대조군으로만 보류 |
| JPS | 균일 grid의 대칭 탐색을 건너뛰어 A*를 가속 | 큰 균일 grid에서 효과적이다. | 작은 지도, 가중 비용, 방향 제약에서는 장점이 줄고 기능 범위를 늘리지 않는다. | 현재 연구 우선순위 낮음 |
| Hybrid A* | 연속 위치·방향과 자동차형 motion을 search | 비홀로노믹·곡률 제약이 강한 차체에 적합하다. | 자동차형 전제와 smoothing·collision checking이 필요해 현재 정보로는 과도하다. | 하드웨어 조건부 보류 |
| State Lattice | 사전 정의한 수행 가능 motion primitive를 graph edge로 사용 | 비원형 차체와 differential-drive의 실제 움직임을 반영할 수 있다. | primitive 생성, 차체·회전 수치와 collision 검증이 필요하다. | **차체 조건부 비교 후보** |
| HPA*/Contraction Hierarchies | 큰 graph를 계층화·전처리해 빠르게 질의 | 도시·게임 대형 map에 유리하다. | 단층 축소 병원과 한 대의 로봇에는 전처리·갱신 비용이 과도하다. | 현재 연구 우선순위 낮음 |
| PRM/RRT/RRT* | 연속·고차원 공간을 sampling | 복잡한 구성 공간에서 유용하다. | 작은 알려진 2D 공간에서는 비결정성·샘플 수·후처리 부담이 크다. | 현재 연구 우선순위 낮음 |

[Dijkstra 원 논문](https://doi.org/10.1007/BF01386390)과 [A* 원 논문](https://doi.org/10.1109/TSSC.1968.300136)은 각각 최단 경로 기준과 heuristic search의 출발점이다. [D* Lite](https://www.cs.cmu.edu/~motionplanning/papers/sbp_papers/integrated3/koenig_dstarlite_aaai02b.pdf)는 변경된 edge 비용과 이동하는 시작점에서 이전 탐색 정보를 재사용한다. 이 성질 때문에 D* Lite의 비교 가치는 `동적 사람이 있다`가 아니라 `같은 map에서 작은 비용·폐쇄 변화가 반복된다`는 조건에서 생긴다.

[State Lattice](https://www.cs.cmu.edu/~alonzo/pubs/papers/isairas05Planning.pdf)와 [Hybrid A*](https://ai.stanford.edu/~ddolgov/papers/dolgov_gpp_stair08.pdf)는 위치뿐 아니라 실제 운동 가능성을 search 상태·연결에 넣는 접근이다. 차체가 제자리 회전할 수 있는지조차 미정인 현재는 우선 채택할 수 없지만, 2D A*가 만들 수 있는 경로와 실제 차체 움직임이 어긋날 경우 반드시 다시 비교해야 한다.

### 2.2 전역 후보의 연구 판정

1. 동일한 graph와 비용 표현을 승인할 경우 Dijkstra를 A*·D* Lite 결과의 비용을 검증하는 oracle로 사용할 수 있다.
2. 작은 등록 통로 graph를 선택할 경우 A*를 첫 단순 기준 후보로 비교할 수 있다.
3. D* Lite는 연속적인 부분 폐쇄 시험에서 A* 재실행보다 실제 계산·경로 안정성 이득이 확인될 때만 남긴다.
4. 2D 경로를 실제 차체가 수행하지 못하는 사례가 확인되면 State Lattice를 별도 차체 가능성 후보로 올린다.
5. 다른 후보는 현재 시나리오에서 새로운 필수 기능을 제공하는지 입증되기 전에는 범위를 늘리지 않는다.

## 3. 제한적 경로 수정과 경로 추종 후보

### 3.1 서로 다른 역할

| 계열 | 실제 역할 | 자체적으로 새 우회 경로를 만드는가? | 대표 입력 |
|---|---|---:|---|
| RPP/Pure Pursuit | 기존 경로 추종과 곡률·장애물 근접 감속 | 아니요 | 기준 경로, 현재 자세·속도 |
| DWA/DWB | 짧은 시간 동안 가능한 속도 궤적을 표본화하고 점수화 | 제한적으로 가능 | 현재 운동, local 장애물, 차체 한계, 기준 경로 |
| Elastic Band/TEB | 기존 경로를 장애물에서 밀어내고 시간·운동 제약에 맞게 변형 | 기존 topology 안에서 가능 | 충돌 없는 초기 경로, 장애물, 차체·시간 제약 |
| VFH+/Follow-the-Gap | 거리 관측에서 통과 가능한 방향·간격 선택 | 반응형으로 가능 | local 거리·점유 정보, 목표 방향 |
| APF | 목표 인력과 장애물 척력을 합성 | 반응형으로 가능 | 목표·장애물 상대 위치 |
| MPC/MPPI | 미래 제어열을 model·cost로 최적화 또는 표본화 | 구성에 따라 가능 | 운동 model, 기준 경로, 제약, 장애물 |

### 3.2 DWA/DWB

[DWA 원 논문](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance)은 현재 속도에서 짧은 시간 안에 도달 가능한 속도와 model 안에서 장애물 앞에 제동 가능한 것으로 판정되는 속도를 탐색한다. 계산이 비교적 작고 differential-drive 축소 차체와 비교하기 쉽다. 이 `admissible velocity`는 정확한 장애물 형상, 현재 상태, 제동 성능과 갱신 조건을 전제로 한 알고리즘 내부 조건이며 제품의 실제 안전정지를 보장하지 않는다.

그러나 기본 DWA는 보행자의 미래 의도를 아는 알고리즘이 아니다. local 표본 범위 밖에 있는 우회로, U자 함정, 좁은 통로 교착과 장애물이 모든 후보를 가리는 상황에서는 멈추거나 진동할 수 있다. [DWB 공식 문서](https://docs.nav2.org/configuration/packages/configuring-dwb-controller.html)는 trajectory generator와 여러 critic으로 이 구조를 일반화하지만 가중치·표본 범위에 대한 튜닝 부담이 남는다.

판정: local 연속 우회를 MVP 범위로 정할 경우 **핵심 비교군**이다. 전체 통로 재선택을 대신하지 않는다.

### 3.3 Elastic Band와 TEB/H-TEB

[Elastic Bands](https://9p.io/who/seanq/icra93.pdf)는 기존 전역 경로를 장애물 주변에서 고무줄처럼 변형한다. 사용자가 말한 `장애물 주변만 돌아간 뒤 원래 경로로 복귀`에 가장 직접적으로 대응한다. 다만 원 논문도 닫힌 문처럼 경로의 연결 관계가 바뀌면 local band만으로 해결할 수 없고 global search가 필요하다고 밝힌다.

[TEB](https://files.davidqiu.com/research/papers/2013_rosmann_TEB%20Planner%20Efficient%20Trajectory%20Optimization%20using%20a%20Sparse%20Model%20%5BECMR%202013%5D.pdf)는 경로 자세와 그 사이의 시간 간격을 함께 최적화해 속도·가속도·비홀로노믹 제약을 반영한다. H-TEB는 서로 다른 topology의 local 후보를 함께 비교하지만 계산·튜닝 범위가 늘어난다.

판정: 경로 모양·승차감·운동 제약을 포함한 **핵심 비교군**이지만, 작은 POC에서 DWA/DWB보다 항상 우월하다고 가정하지 않는다.

### 3.4 RPP

[Regulated Pure Pursuit](https://arxiv.org/abs/2305.20026)는 곡률과 장애물 근접도 등에 따라 속도를 조절하며 이미 주어진 경로를 안정적으로 추종하는 데 초점을 둔다. [Nav2 튜닝 문서](https://docs.nav2.org/tuning/index.html)도 RPP를 경로를 정확히 따라가는 controller로 설명하고 DWB·MPPI 계열의 경로 이탈 가능성과 구분한다.

판정: 우회 경로를 생성하지 않는 경로 추종·속도조절 대조군이다. 충돌 예상 시 정지 명령을 생성할 수 있지만 실제 안전정지와 이동 허가는 별도 안전 계층의 책임이다. 국소 경로 수정 알고리즘 후보로 점수를 주면 안 된다.

### 3.5 VFH+, Follow-the-Gap와 APF

[VFH+](https://www.cs.cmu.edu/~motionplanning/papers/sbp_papers/integrated1/borenstein_VFHplus.pdf)는 local 거리 정보를 극좌표 장애물 밀도로 바꾸고 차체 크기·회전 조건을 고려해 진행 방향을 고른다. Follow-the-Gap은 관측된 빈 간격을 고르는 더 단순한 반응형 대조군이다. 계산량이 작아 Python·Unity에서 실패 형태를 보여주기 좋지만 U자 공간, 가려짐, 좌우 진동과 원 경로 재합류가 약점이다.

[Khatib의 APF](https://khatib.stanford.edu/publications/pdfs/Khatib_1986_IJRR.pdf)는 매우 단순하지만 local minimum과 좁은 구간 진동 때문에 교육용 최저 기준선 이상으로 채택하기 어렵다.

판정: VFH+/Follow-the-Gap은 저연산 대조군, APF는 실패 사례 교육용 대조군이다. 단독 본선 후보는 아니다.

### 3.6 MPC/MPPI

[Nav2 MPPI](https://docs.nav2.org/configuration/packages/configuring-mppic.html)는 운동 model에 따라 많은 미래 제어열을 표본화하고 비용이 낮은 것을 선택한다. 복잡한 비선형 비용과 차체 제약을 넣기 쉽지만 계산 자원, model 오차, 비용함수 튜닝과 deadline miss를 검증해야 한다. 장애물 비용이 soft cost이면 별도 validator 없이 안전을 주장할 수 없다.

판정: 계산 장치·주기와 연속 local 우회가 MVP 필수임이 확인될 때의 고급 조건부 후보다. 현재 우선 후보로 고정하지 않는다.

## 4. 동적 장애물 후보

### 4.1 동적이라는 이유만으로 계속 피해서 갈 필요는 없다

움직이는 사람은 잠시 뒤 지나갈 수 있고, 정지한 사람도 갑자기 다시 움직일 수 있다. 따라서 물체 label보다 다음을 판단해야 한다.

- 충돌 가능성을 현재 정보로 배제할 수 있는가?
- 대상의 상태·속도·진행 방향을 얼마나 신뢰할 수 있는가?
- 안전하게 기다릴 공간이 있는가?
- 통로 연결이 실제로 끊겼는가?
- local 이탈 뒤 다시 합류할 수 있는가?

현재 기준선은 충돌 가능성을 배제할 수 없으면 먼저 정지하고, 대체 이동의 안전성을 충분히 판단할 수 없으면 정지를 유지하는 것까지만 승인한다. 기다린 뒤 재평가할지와 그 시점·조건은 후속 미정이다. 따라서 `정지 유지 → 현재 허용된 재판단`을 공통 기준으로 두고, 기다림은 추후 승인될 경우에만 별도 정책 후보로 비교한다.

### 4.2 현재 관측 반응과 미래 예측의 분리

`동적 장애물용 local planner`라는 한 묶음도 정확하지 않다.

- DWA/DWB, 기본 TEB와 일반 costmap 기반 MPPI는 갱신된 현재 장애물 관측에 반응하는 local trajectory 계열이다. 그 자체가 보행자의 미래 궤적을 예측하지는 않는다.
- TEB의 동적 장애물 확장은 추적된 장애물 속도와 대체로 등속도 예측에 의존하며, [공식 ROS 패키지 설명](https://index.ros.org/p/teb_local_planner/)에서는 실험적 기능으로 다뤄진다.
- MPPI도 시간별 장애물 예측 입력과 그 비용 구성이 없으면 미래 사람 운동을 자동으로 예측하지 않는다.
- VO/RVO/ORCA는 상대 위치·속도로 시간적 충돌을 예측하지만 상태 정확도와 협력 가정이 강하다.
- SIPP는 미래 trajectory에서 계산한 안전 시간 구간을 요구한다.

따라서 현재 관측만 받는 후보와 미래 예측을 받는 확장을 같은 입력 조건으로 평가하거나, 전자를 `사람 움직임 예측 알고리즘`이라고 부르지 않는다.

### 4.3 VO/RVO/ORCA

[Velocity Obstacles](https://journals.sagepub.com/doi/pdf/10.1177/027836499801700706)는 상대 위치·속도에서 미래 충돌을 만드는 속도 집합을 제외한다. [ORCA](https://gamma-web.iacs.umd.edu/ORCA/)는 여러 agent가 회피 책임을 나눈다는 가정 아래 효율적으로 충돌 회피 속도를 구한다.

병원 보행자·병상·카트는 같은 protocol을 따르는 협력 agent가 아니다. 기본 ORCA의 정확한 상태·협력·holonomic 운동 가정도 differential-drive 휠체어에 그대로 맞지 않으며, 적용하려면 ORCA-DD 같은 확장을 별도로 검토해야 한다. 속도 추정 오차, 급정지, 좁은 문과 상호 정지 교착도 남는다. 따라서 ORCA는 실제 휠체어의 단독 safety planner보다 Unity 군중 생성, 동적 위험 평가 또는 후보 속도 필터로 검토한다.

### 4.4 SIPP와 시간 기반 계획

[SIPP](https://www.cs.cmu.edu/~maxim/files/sipp_icra11.pdf)는 각 위치가 안전한 시간 구간을 저장해 기다렸다가 통과하는 경로를 찾는다. 미래 trajectory가 공유되는 다른 자율휠체어나 예약형 이동체에는 의미가 있다. 반면 예측하기 어려운 사람에게는 safe interval 자체가 틀릴 수 있고, 원형 SIPP의 순간 정지 가정은 실제 차체에 맞지 않는다. [Kinodynamic SIPP 확장](https://ojs.aaai.org/index.php/AAAI/article/download/26453/26225)은 이 한계를 줄이지만 입력·계산 복잡성을 늘린다.

판정: 제어되는 다른 휠체어가 자신의 미래 경로를 공유하는 확장 단계에서는 보류 후보이며, 현재 한 대 POC의 사람 대응 후보에서는 우선 제외한다.

### 4.5 사회적·학습형 navigation

군중 연구는 단순 반응형 planner가 혼잡 환경에서 멈춰 버리는 `freezing`과 비협력 계획의 한계를 보여준다. 그러나 Social-RL은 학습 분포 밖 병원 행동, 설명 가능성, 재현성과 안전 경계 문제가 남는다.

판정: [SocNavBench](https://arxiv.org/abs/2103.00047), [SocNavGym](https://arxiv.org/abs/2304.14102), [HuNavSim](https://arxiv.org/abs/2305.01303)에서 시나리오·평가 지표만 가져오고, 학습형 controller를 현재 제품 후보로 넣지 않는다.

## 5. 서로 반대되는 연구 결과가 의미하는 것

local planner 순위를 일반화하면 안 된다.

- [Arena-Bench](https://arxiv.org/abs/2206.05728)는 동일한 planner도 로봇 운동 특성, scene과 sim-real 차이에 따라 결과가 달라짐을 보여준다.
- [DynaBARN](https://www.cs.utexas.edu/~pstone/Papers/bib2html/b2hd-ssrr22-nair.html)은 동적 장애물의 속도·가감속·움직임 profile을 바꾸면 DWA와 TEB의 상대 결과가 달라질 수 있음을 보여준다.
- [BARN](https://www.cs.utexas.edu/~xiao/BARN/BARN.html)은 정적 밀집 공간의 반복 시험에는 유용하지만 동적 보행자 안전을 증명하지 않는다.

이 결과는 논문 수로 우승자를 정할 것이 아니라 같은 map, 차체, 장애물 sequence, 계산 자원과 tuning budget에서 직접 비교해야 한다는 근거다.

## 6. 다른 분야에서 가져온 선정 원칙

### 6.1 게임 AI: 이동 중 회피와 지속 폐쇄 분리

[Unity NavMesh Obstacle](https://docs.unity.cn/Manual/class-NavMeshObstacle.html)은 움직이는 장애물을 짧은 범위 회피 대상으로 처리하고, 일정 시간 정지한 장애물은 navmesh를 carve해 pathfinder가 다른 길을 찾게 한다. 게임 구현을 실물에 복사할 수는 없지만 다음 구분은 유용하다.

- 잠깐의 움직임에는 경로 topology를 계속 바꾸지 않는다.
- 지속적으로 통로 연결을 끊는 장애물은 global route에 반영한다.
- local 결과와 global 결과가 번갈아 적용돼 route churn이 생기지 않는지 본다.

### 6.2 도로 교통: 기다림과 우회 비용 분리

[SUMO Rerouter](https://sumo.dlr.de/docs/Simulation/Rerouter.html)는 구간 폐쇄 시 우회뿐 아니라 폐쇄가 풀리기를 기다리는 선택을 다룬다. 여러 판단자가 서로 다른 폐쇄 정보를 보면 반복 reroute가 생길 수도 있다.

병원 복도에서 얻는 질문은 `장애물이 동적인가`만이 아니다.

- 곧 사라질 수 있는 장애물 앞에서 긴 우회가 더 나은가?
- 어느 시점에 일시 장애물을 통로 폐쇄로 승격하는가?
- 모든 계층이 같은 폐쇄·지도 version을 보고 있는가?

기다림 시간이나 전환 임계값은 아직 정하지 않는다.

### 6.3 창고·시설 로봇: 충돌 0이 임무 성공은 아님

[Open-RMF](https://osrf.github.io/ros2multirobotbook/rmf-core.html)는 전역 일정·통로 conflict와 각 로봇 local navigation을 분리한다. 현재는 한 대이므로 fleet negotiation을 구현할 이유가 없지만, 좁은 복도에서 외부 휠체어와 서로 영원히 멈추는 결과를 안전 성공만으로 기록하면 안 된다. 교착, 지원 전환과 임무 미완료를 별도로 평가한다.

### 6.4 자동차·항공·산업 안전: 계획 결과와 실행 허가 분리

[Autoware Planning Validator](https://autowarefoundation.github.io/autoware_universe/main/planning/planning_validator/autoware_planning_validator/)는 control에 넘기기 전 trajectory의 유효성과 최신성을 별도로 검사한다. [Nav2 Collision Monitor](https://docs.nav2.org/configuration/packages/collision_monitor/configuring-collision-monitor-node.html)는 controller 출력 뒤에서 stop·slow zone을 적용한다. 공식 문서도 이것이 인증된 hard real-time safety 장치라고 주장하지 않는다.

[Simplex architecture](https://www.sei.cmu.edu/library/an-architectural-description-of-the-simplex-architecture/)와 [NASA Runtime Assurance](https://ntrs.nasa.gov/citations/20220015734)는 복잡한 고성능 controller와 단순한 안전 fallback을 분리하는 공통 원칙을 제공한다.

프로젝트에 적용할 상위 원칙은 다음뿐이다.

```text
경로 후보 생성
→ 현재 미션·지도·장애물 정보와 일치하는지 검증
→ 로봇이 실제로 정지했는지 확인
→ 별도 local safety gate가 이동을 허가할 때만 실행
→ 입력이 오래됐거나 계산이 실패하면 정지 유지
```

구체 message field, version 형식, heartbeat 주기와 물리 회로는 아직 확정하지 않는다.

## 7. 26개 시나리오와 후보의 대응

| 시나리오 묶음 | 조건이 맞을 때 비교할 기능 | 반드시 보존할 결과 |
|---|---|---|
| A-01/A-02 정상 이동 | 전역 A* + 추종 대조군 | 불필요한 정지 없이 같은 목적지 진행 |
| A-03/A-04 경로 없음·판단 불충분 | 모든 후보 | 출발 억제 또는 정지 유지 |
| A-08 위치·경로 판단 불충분 | 모든 후보 외부 validator | planner 결과와 무관하게 정지 |
| S-01 일부 정적 점유 | bounded local A* 가설, DWA/DWB, TEB | 먼저 정지 후 허용된 local 수정 또는 정지 유지 |
| S-02 통로 전체 폐쇄·대체 통로 존재 | graph A*, D* Lite 조건부 | 같은 목적지의 다른 통로 또는 정지 유지 |
| S-03 모든 허용 경로 차단 | 모든 global 후보 | 경로 없음 검출, 정지·지원 전환 |
| S-05 지도·실제 불일치 | validator와 입력 최신성 정책 | 오래된 경로 실행 금지 |
| D-01/D-06 일시 횡단·정지 전환 | 정지 유지·재판단 기준, 기다림 정책은 승인 시 별도, DWA/TEB는 연속 회피 범위일 때 | 자동 재출발 전 재판단 |
| D-02/D-03/D-04 좁은 통로·정면·느린 대상 | DWA/TEB/VO 보조 비교 | 충돌 0뿐 아니라 교착·후퇴·지원 필요 기록 |
| D-05/D-07/D-08 갑작스러운·복잡한 대상 | 모든 local 후보 + 독립 정지 | 예측 실패·불확실 시 정지 유지 |
| C-01/C-03 혼합·우회 중 새 장애물 | 조합 정책 | 현재 대체 경로 폐기 후 다시 정지·판단 |
| C-02/C-04/C-05 불확실·자동 해결 불가·교착 | 모든 후보 | 정지 유지와 사람 지원 결과 |
| R-01 위험 해소 | 추종기와 safety gate | 해소 관측만으로 움직이지 않고 재검증 |

## 8. 같은 조건 비교 설계

이 절은 구현 계획이 아니라 후보 선정에 필요한 실험 설계다.

### 8.1 1차: Python 논리 환경

센서 종류를 가정하지 않고 완전한 ground truth를 입력해 알고리즘 자체의 차이를 먼저 본다.

#### 전역 후보 지도

- 갈림길이 있는 등록 통로 graph
- 현재 통로 하나만 폐쇄된 경우
- 목적지와 무관한 통로가 폐쇄된 경우
- 여러 폐쇄가 순차적으로 추가·해제되는 경우
- 모든 대체 통로가 폐쇄된 경우
- 시작점이 이동한 뒤 같은 목적지로 다시 계산하는 경우
- 목적지가 바뀐 경우

#### local 후보 지도

- 넓은 구역에서 기존 경로 일부만 점유
- 좁은 문·복도
- U자 함정
- 사각 모퉁이
- 우회는 가능하지만 원 경로 재합류가 불가능한 경우
- 우회 중 새 장애물이 나타나는 경우

#### 동적 sequence

- 횡단, 정면 접근, 추월
- 갑자기 정지·재출발
- 가려진 곳에서 등장
- 여러 대상과 비협력 대상
- 움직이다 통로에 정지해 지속 폐쇄로 바뀌는 경우

#### 결과 최신성과 global↔local 인계 sequence

다음 시험은 구체 version field나 message 형식을 확정하지 않고 사건 순서와 보수적 기대 결과만 정의한다.

- 이전 미션에서 계산한 경로가 새 미션 시작 뒤 늦게 도착함 → 현재 미션과 불일치한 결과를 실행하지 않고 정지 유지
- 경로 계산 중 사용 가능한 지도가 변경됨 → 이전 지도에 대한 결과를 폐기하거나 최신 지도에 대해 다시 검증
- local 우회 중 새 global 경로가 도착함 → 현재 위치에서 수행 가능하고 허용된 안전한 인계 지점을 확인하기 전에는 전환하지 않음
- 로봇이 예정 인계 지점을 지난 뒤 후보 경로가 늦게 도착함 → 지난 지점으로 즉시 되돌리거나 오래된 후보를 그대로 실행하지 않고 재검증
- 위험 해소가 관측됐지만 실제 정지 완료가 확인되지 않음 → 이동 재개 금지
- 같은 통로의 차단·해제가 반복됨 → global 경로가 끝없이 왕복하지 않는지 기록하되, 경로 안정화 정책이 즉시 안전정지를 지연시키면 탈락
- local 우회 중 새 장애물이 나타남 → 현재 우회 후보를 계속 신뢰하지 않고 다시 정지·판단
- 경로 계산이 deadline 뒤 완료됨 → 현재 상황에서 여전히 유효한지 확인할 수 없으면 실행하지 않음

[MovingAI Benchmarks](https://movingai.com/benchmarks/)는 grid와 start-goal scenario를 재현하는 보조 자료로 쓸 수 있고 현재 사이트는 자료를 ODC Attribution License로 제공한다고 명시한다. 다만 병원 공간·차체·동적 사람을 대표하는 자료는 아니므로 자체 추상 시나리오가 기준이다.

### 8.2 2차: Unity 시각 환경

Python에서 기능 차이가 확인된 후보만 Unity에서 비교한다.

- 병원 복도 폭·문·교차점과 사각 공간의 시각 확인
- 사람에게 움직임이 예측 가능해 보이는지 확인
- 반복 정지·출발, 좌우 진동, 불필요한 후진과 route churn 확인
- 같은 시나리오를 영상으로 설명할 수 있는지 확인

Unity의 성공은 실제 제동거리·센서 지연·물리 안전 증거가 아니다.

### 8.3 후보별 공정 비교 조건

모든 후보에 다음 조건을 동일하게 둔다.

- 동일 map, 해상도, 허용·금지 구역과 unknown 처리
- 동일 차체 footprint, 회전·속도·가감속·정지 model
- 동일 시작점·목적지·장애물 sequence·random seed
- 동일 장애물 관측 지연·누락과 위치 오차 주입
- 동일 CPU·memory·계산 deadline
- 동일 tuning 시간과 공개되지 않은 평가 시나리오
- 동일 외부 safety gate와 실패 timeout
- 반복 시험과 p50/p95/p99·최악값 기록

전역 search의 계산시간과 local controller를 포함한 종단 성공률을 직접 비교하지 않는다. 서로 다른 센서 정보, footprint나 tuning 시간을 쓴 결과도 같은 순위표에 넣지 않는다.

## 9. 평가 지표와 탈락 조건

### 9.1 역할별 지표

| 계층 | 주요 지표 |
|---|---|
| 전역 | Dijkstra 최단 비용 대비 차이, 최초·재계산 시간, 확장 node 수, memory, no-path 검출, 경로 switching 횟수 |
| local | 충돌, 최소 간격, 성공률, 원 경로 최대 이탈·재합류, 정지·동결 시간, 좌우 진동, 후진, 거리·시간 |
| 추종 | 횡방향·방향 오차, overshoot, 속도·가속도·jerk, 정지 명령 뒤 추가 이동 |
| 동적 | TTC, near miss, 기다림, 예측 실패, 교착·지원 전환, 비협력 대상에서의 결과 |
| 시스템 | 계산 deadline miss, 오래된 결과 거부, 입력 누락 시 fail-stop, 동일 seed 재현성 |

외부 벤치마크가 충돌을 일부 허용한 결과를 `success`로 계산하더라도 이 프로젝트의 안전 성공으로 인정하지 않는다.

### 9.2 즉시 탈락 조건

후보가 아래 중 하나라도 만족하면 높은 평균 성공률과 무관하게 현재 후보에서 탈락시킨다.

- 현재 map·차체·정지 model로 수행할 수 없는 경로를 정상 결과로 낸다.
- 장애물·위치·지도 입력이 오래되거나 불확실한데 계속 이동을 요구한다.
- 서버 응답 없이 local 안전정지를 시작할 수 없는 구조를 전제로 한다.
- 정지 명령과 실제 정지 완료를 같은 것으로 취급한다.
- 장애물이 사라졌다는 관측 또는 planner 성공만으로 자동 재출발한다.
- 이전 미션·이전 지도·이전 장애물 상태의 경로를 새 상황에서 실행한다.
- local 우회가 허용 구역을 벗어나거나 안전한 재합류 지점을 제시하지 못한다.
- 계산 deadline을 반복해서 넘기면서 실패를 정지 상태로 닫지 못한다.
- 경로 없음·판단 불충분·지원 필요를 명시적으로 구분하지 못한다.
- 실제로 제공할 수 없는 미래 사람 trajectory나 완전한 상태 정보를 필수 전제로 한다.
- simulation 성공만으로 실물 안전을 주장해야 성립한다.
- 동일 입력과 seed에서도 설명하기 어려운 결과 변동을 보이고 이를 통제할 수 없다.

## 10. 역할별 조건부 후보 압축 결과

이 절은 알고리즘 전체 순위를 매기지 않는다. 각 역할의 진입 조건이 승인될 경우에만 그 역할 안에서 비교할 후보를 줄인다.

### 10.1 전체 경로 search

등록 통로 graph 또는 이에 준하는 연결 표현을 승인할 경우 다음 비교가 가능하다.

- **Dijkstra**: 동일한 정적 graph·동일 비용 model에서 최단 비용 검산용
- **A***: 단순 재탐색 기준 후보
- **D* Lite**: 같은 목적지에서 작은 edge 변화가 반복되는 경우의 조건부 후보

2D 위치 경로를 실제 차체가 수행할 수 없는 사례가 확인되면 이 비교와 별도로 **State Lattice**를 차체 수행 가능성 후보로 올린다.

### 10.2 제한적 local 경로·궤적 생성

local 공간 표현, 허용 이탈·재합류 범위와 연속 local 수정 기능을 승인할 경우 다음 후보를 같은 역할 안에서 비교할 수 있다.

- **제한 영역 A* 가설**: 정적 일부 점유에서 작은 공간 경로를 새로 찾는 프로젝트 전용 가설
- **DWA/DWB**: 현재 관측과 짧은 속도 trajectory에 반응하는 기준 후보
- **TEB/H-TEB**: 기존 경로의 공간·시간·운동 제약 최적화 후보
- **MPPI**: 계산 장치·model·tuning·deadline 검증 여력이 있을 때의 고급 후보

비교할 때는 동일한 global 경로 입력, footprint, 외부 validator와 safety gate를 사용한다. 한 후보가 path를 내고 다른 후보가 motor command를 내면, 동일한 추종 wrapper까지 포함한 완성 stack 단위로 별도 비교하며 component 순위와 섞지 않는다.

### 10.3 동적 대상의 시간 정책과 예측

- **현재 승인 기준**: 충돌 가능성을 배제할 수 없으면 정지하고, 안전성을 충분히 판단할 수 없으면 정지 유지
- **조건부 정책 후보**: 팀이 승인할 경우의 기다림·재평가 정책
- **현재 관측 반응 후보**: DWA/DWB, 기본 TEB, 일반 costmap 기반 MPPI
- **미래 예측 입력 후보**: 동적 TEB 확장, 예측 trajectory를 받는 MPPI, VO/ORCA
- **정확한 미래 경로가 공유될 때만 보류**: SIPP

정지 유지, 기다림 정책, local trajectory 생성과 미래 충돌 예측은 서로 다른 역할이므로 한 점수표에서 직접 우열을 매기지 않는다. 최종적으로 비교할 필요가 생기면 각 역할을 조합한 완성 stack에 동일한 map·입력·추종기·validator를 적용한다.

### 10.4 경로 추종

- **RPP 또는 단순 waypoint 추종**은 우회 기능이 없는 공통 추종 대조 아이디어다.
- 실제 차체·제어 주기를 확인하기 전에는 어느 추종기를 채택하지 않는다.
- local path 후보를 비교할 때 추종기 차이가 결과를 가리지 않도록 같은 추종기를 사용한다.

### 10.5 현재 조사 우선순위가 낮은 후보

- 실패 형태를 보여주는 연구 대조군: APF, VFH+/Follow-the-Gap, 원형 Elastic Band, Theta*, Unity NavMesh
- 현재 작은 알려진 공간에서 새 기능 대비 복잡성이 큰 후보: 원형 D*, HPA*, Contraction Hierarchies, JPS, ARA*, AD*, PRM, RRT, RRT*
- 현재 입력 신뢰도·검증 범위에 맞지 않는 후보: 사람 미래 trajectory를 전제로 한 SIPP 실주행, 순수 Social-RL navigation
- 직접 도입 범위가 지나치게 큰 stack: 전체 Open-RMF·Autoware

연구 우선순위가 낮다는 것은 기술이 나쁘거나 MVP에서 이미 제외됐다는 뜻이 아니다. 지도, 차체, 입력과 제품 범위가 달라지면 다시 후보로 올릴 수 있다.

## 11. 알고리즘을 최종 채택하기 전에 필요한 결과

다음 결과가 나오기 전에는 구체 알고리즘을 최종 확정하지 않는다.

1. 시연 map에 갈림길과 실제 대체 통로가 있는지 확인한다. `[G1, MAP-03]`
2. local 이탈·재합류가 허용되는 공간을 정한다. `[MAP-02/08]`
3. 차체 footprint, 제자리 회전 가능 여부와 최소 회전 공간을 확인한다. `[G2, VEH-01/02]`
4. 경로 기능이 받을 장애물 정보가 단순 점유인지 개체 속도·신뢰도까지인지 확인한다. `[G3, OBS-02/03/04/06]`
5. 실행 장치의 계산 자원·주기와 planner가 실행될 위치를 확인한다. `[G4, SYS-01/06]`
6. 동적 대상을 피해 계속 움직이는 기능을 실물 MUST, simulation, 이후 확장 중 어디에 둘지 정한다. `[G5]`
7. 위 동일 조건 시험에서 전역 계층은 A* 재실행과 D* Lite를, local 계층은 같은 출력·추종 wrapper를 둔 제한 영역 탐색 가설과 DWA/TEB 계열을 각각 분리해 확인한다.

이 중 1~6은 최종 채택을 위한 팀 입력이고, 7의 Python 비교 설계까지는 Software A가 독자적으로 준비할 수 있다.

## 최종 연구 판정

폭넓은 문헌에서 반복되는 결론은 `전역 하나 + local 하나를 무조건 결합하라`가 아니다.

- 기존 경로 주변에 안전한 변형·재합류 공간이 남아 있으면 local 수정이 의미가 있다.
- 문·복도 폐쇄처럼 연결 관계가 끊기면 global 재선택이 필요하다.
- 대상 예측, 위치, 지도 또는 정지 여유가 불확실하면 어느 planner보다 정지가 먼저다.
- 실제 이동 허가는 경로 계산 결과와 분리해야 한다.

따라서 현재 가장 합리적인 다음 작업은 후보를 바로 구현하는 것이 아니라 역할별 조건부 비교표를 확정하는 것이다.

1. `지도 표현`: graph, grid와 방향 포함 lattice가 어떤 입력 조건에서 성립하는지 비교
2. `전역 search`: 동일한 graph·비용에서 Dijkstra 검산, A*와 D* Lite 조건부 비교
3. `local 경로·궤적`: 같은 global 입력·추종 wrapper·validator 아래 제한 영역 탐색 가설, DWA/DWB와 TEB 조건부 비교
4. `동적 시간 정책`: 승인된 정지 유지·재판단을 기준으로 두고, 기다림은 승인 시 별도 비교하며 현재 관측 반응과 미래 예측 확장을 분리
5. `경로 추종`: local 후보와 섞지 않고 동일 추종기를 공통 적용

그 결과와 G1~G5가 합쳐진 뒤 `제품 확장 구조`와 `2026 대회 MVP 구조`를 따로 채택한다.
