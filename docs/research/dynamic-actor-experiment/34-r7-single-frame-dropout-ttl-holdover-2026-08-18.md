# R7 단일 관측 누락과 TTL 재사용 명세

## 목적

Normal 관측은 10 Hz이고 frame dropout은 5%다. 기존 구현은 카메라 frame 하나가
빠질 때마다 마지막 유효 정보가 아직 `300 ms` TTL 안에 있어도 즉시 제동했다. 이 때문에
안전 위반은 없었지만, 같은 경로를 반복해서 멈추고 다시 시작하느라 일부 사례가 80초 안에
끝나지 못했다.

이번 변경은 마지막 유효 관측을 TTL 안에서 잠깐 재사용한다. 실제 카메라 성능이나 실제
사람 추적 성능을 주장하지 않으며, 합성 관측 연구 하네스에만 적용한다.

## 고정 규칙

```text
새 frame 도착
→ 평소처럼 검증·방향 계산

frame 하나 누락
→ 마지막 유효 frame의 나이가 300 ms 이하인지 확인
→ 같은 stream·mission·map·track인지 확인
→ 이미 20개 frame으로 방향 계산이 끝난 상태면 마지막 정보를 현재 시각까지 보수적으로 확대해 사용
→ 기존 이동만 계속할 수 있음

나이 300 ms 초과 또는 identity/hash 불일치
→ 제한 감속
→ 실제 정지 뒤 hold
```

## 재사용 정보로 할 수 없는 것

재사용한 frame은 새 카메라 정보가 아니다. 따라서 다음에는 사용할 수 없다.

- 20개 방향 계산 history를 늘리지 않는다.
- 안전 frame 11개 확인 수를 늘리지 않는다.
- 최초 출발을 허가하지 않는다.
- 보호정지 뒤 재출발을 허가하지 않는다.
- Actor 추월 완료를 새로 증명하지 않는다.

이미 이동 중인 명령의 `CONTINUATION`에만 사용할 수 있다. 이미 새 frame으로 추월 완료가
증명된 상태라면 그 기존 증명을 TTL 안에서 유지할 수 있지만, 누락 frame으로 새 추월 증명을
만들 수는 없다.

## Empty와 연속 누락

- 실제로 도착한 `EMPTY` frame은 사람 없음이라는 새 관측이다.
- 그 다음 frame이 한 번 빠지면 마지막 `EMPTY`도 TTL 안에서만 유지할 수 있다.
- 연속 누락으로 마지막 frame 나이가 `300 ms`를 넘으면 반드시 정지한다.
- Stress의 `250 ms` 지연에서는 한 번의 추가 누락만으로 stale이 되기 쉬우므로 기존처럼
  보수적 정지가 예상된다.

## 검증 순서

1. 방향 계산 완료 전 dropout은 계속 정지한다.
2. 방향 계산 완료 뒤 단일 dropout은 history를 늘리지 않고 마지막 정보를 재사용한다.
3. 재사용 frame으로 최초 출발·재출발·새 추월 증명을 만들 수 없다.
4. `age > 300 ms`, invalid, hash·identity 불일치는 정지한다.
5. 대표 public Normal 사례에서 단일 dropout 때문에 즉시 제동하지 않는지 확인한다.

이 명세의 통과는 실제 카메라, 네트워크, 사람 탑승 안전 또는 제품 자동재출발의 증거가 아니다.
