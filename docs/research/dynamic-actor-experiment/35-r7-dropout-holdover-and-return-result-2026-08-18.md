# R7 단일 관측 누락 재사용과 원 경로 복귀 결과

## 결론

Normal에서 카메라 frame 하나가 빠졌을 때 마지막 정보가 `300 ms` TTL 안이면 기존 이동을
계속하도록 수정했다. 누락 frame을 새 정보로 세지는 않는다. 오래 끊기거나 정보가 이상하면
기존처럼 감속·정지한다.

이 수정 뒤 과거에 80초 안에 끝내지 못했던 Normal 3건은 모두 목적지까지 완료했다.

## 발견한 코드 문제

문제는 두 가지였다.

1. frame 하나가 빠질 때마다 방향 계산기·경로 계산기·안전장치가 모두 즉시 정지했다.
2. 사람을 지나쳤다는 확인 뒤 원 경로로 바로 바꾸지 않고, 다음 관측 누락이 생겨 정지할 때까지
   기다렸다. 누락이 줄자 우회 경로를 그대로 타고 목적지까지 가서 원 경로 복귀 기록이 빠졌다.

두 번째 문제를 다음 순서로 고쳤다.

```text
사람 통과 확인
→ 다음 tick부터 제한 감속
→ 실제 정지 확인
→ 새 stop_epoch
→ 서로 다른 새 안전 frame 11개 확인
→ 원 경로용 새 session과 새 이동 허가
→ 목적지 완료
```

우회 session에서만 위 정지를 한 번 요청한다. 원 경로 session이 시작된 뒤 같은 정지 조건을
다시 적용하지 않는다.

## 지키는 제한

TTL 안에서 재사용한 frame은 다음에 사용할 수 없다.

- 20-frame 방향 history 증가
- 안전 frame 11개 확인 수 증가
- 최초 출발 또는 보호정지 뒤 재출발
- 새 post-pass 증명

`age > 300 ms`, stale, invalid, 다른 stream·map·track, hash 불일치는 모두 정지한다.
Stress는 기본 지연이 `250 ms`라 한 번 더 누락되면 stale이 되기 쉬우며, 무출발 보수정지 기준을
완화하지 않았다.

## 검증 결과

### 표적·public

- 방향 계산·shared gate·DWB adapter·시간 이동 허가·public context 표적시험: `96 passed`
- R7 public 직접 영향시험: `9 passed`
- R5-C 관측·재개 직접 영향시험: `12 passed`
- 방향 계산 전 dropout: 정지
- 방향 계산 뒤 TTL 안 dropout: 기존 이동 계속
- TTL 경계 `300 ms`: 사용 가능
- TTL 초과: stale 정지
- 누락 frame의 안전 확인 수 증가: `0`
- hard failure: `0`

### 소비된 hidden-v2 회귀자료 3건

새 hidden이 아니라 이미 결과가 공개된 과거 실패 입력을 병렬 재생했다.

| 사례 | 결과 | 완료 tick | 통과 확인 | 원 경로 복귀 | 최소 Actor 여유 |
|---|---|---:|---:|---:|---:|
| `hidden-01-left-normal` | 완료 | `739` | `435` | `494` | `0.2729 m` |
| `hidden-02-left-normal` | 완료 | `711` | `408` | `462` | `0.2670 m` |
| `hidden-04-right-normal` | 완료 | `901` | `360` | `430` | `0.5065 m` |

세 사례 모두 최소 정적 여유 `0.3786 m` 이상, hard failure `0`이었다.

이 결과로 기존 hidden-v2를 PASS로 바꾸지 않는다. 이미 소비된 입력은 회귀자료일 뿐이며,
최종 hidden이 필요하면 새 commitment와 새 seed가 필요하다.

## 남은 검증

- DWB adapter 소스가 바뀌었으므로 R7 50 ms 정식 `500회` 재측정
- 새 hidden 실행은 사용자 별도 승인 전 금지

이 결과는 합성 관측 simulation 연구 결과다. 실제 카메라, 실제 사람, 실물 휠체어, 제품 자동
재출발 또는 사람 탑승 안전의 증거가 아니다.
