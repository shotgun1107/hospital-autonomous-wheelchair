# R5-B 횡단·다중 위험 컨트롤러 실행 보완 명세

- 상태: 구현·공개 Ideal 검증 완료
- 작성일: 2026-08-16
- 범위: 공개 Ideal, 합성 Actor, C++ DWB 기능 연구
- 비범위: 실제 초음파 거리·배치 coverage·반사·무응답·R2-B 센서 판정 변경, Normal·Stress, hidden, 제품 채택

## 1. 목적

같은 방향 Actor 좌·우 10개는 C++ DWB로 이탈→추월→재합류→도착을 확인했다. 다음은
R2-A에 이미 존재하는 두 다른 행동을 persistent C++ DWB와 공통 안전 장치에 연결한다.

1. 옆에서 기준 경로를 가로지르는 Actor를 우회한 뒤 재합류한다.
2. 첫 위험 뒤 움직임을 재개하고, 두 번째 위험에서 별도로 다시 정지한다.

두 결과는 실제 사람 안전, 카메라 인식 또는 제품 알고리즘 채택 증거가 아니다.

## 2. 기존 공개 장면을 그대로 실행할 수 없는 이유

legacy 횡단 Actor는 `2.0s`에 지도 안에서 활성화된다. 방향성 예측은 서로 다른 관측 20개와
`1.9s` 이력이 필요하므로 처음 실행 가능한 시점은 약 `4.0s`다. 기존 R2-A 횡단 witness는
`0s`부터 움직여야 Actor가 경로를 막는 시간 안에 통과한다. 따라서 기존 시간표를 그대로
controller에 주는 것은 인과적으로 불가능하다.

다중 위험도 두 번째 Actor가 중간에 즉시 나타나므로 같은 문제가 있다. 이 문제를 관측 지연,
Capsule 또는 안전거리 완화로 숨기지 않는다.

## 3. 경로 전용 Ideal 파생 장면

controller 기능만 확인하기 위해 Actor의 속도·반경·교차 위치와 차체·지도는 유지하고 시간만
이동한다. 다음 규칙은 횡단 좌·우 장면에 적용한다.

- Actor는 `t=0`부터 지도 밖의 진입선에서 동일한 일정 속도로 이동한다.
- Actor가 반대편 지도 밖으로 나간 뒤에도 episode가 끝날 때까지 같은 track을 유지한다.
- 방향성 예측이 READY가 될 때까지 로봇은 실제 정지를 유지한다.
- 기존 R2-A witness의 모든 움직임과 Actor 차단 구간을 같은 양만큼 뒤로 이동한다.
- 원본의 종료 여유를 잃지 않도록 파생 episode 종료 시각도 같은 `4.0s`만큼 늘린다.
- 이동된 witness를 현재 200Hz 독립 validator로 다시 검증한다.
- 파생 장면·witness·검증 hash를 원본과 별도로 기록한다.

지도 밖 Actor 관측은 합성 `entry portal` 입력이다. 실제 초음파 센서가 지도 밖 사람을 측정해
2차원 track을 만들 수 있다는
주장이 아니며 R2-B hard failure 2건을 닫지 않는다. 출구 쪽 track 유지도 사람이 사라지기 전
보수적인 통과 증거를 확정하기 위한 실험 전용 계약이다.

횡단 곡선의 사건 지점은 강제 정지점이 아니다. 로봇이 다음 연속 구간 위에 있고 경로에서
기존 위치 허용 범위 `0.05m` 안이며, 정지·회전·방향 전환이 없는 바로 다음 구간일 때만 이미
통과한 구간 번호를 한 칸 따라잡는다. 끝점 허용 오차 `0.02m`, 경로 창 후방 범위 `0.10m`,
안전거리는 늘리지 않는다. 이 조건이 하나라도 맞지 않으면 기존처럼 보수적으로 실패한다.

다중 위험 장면은 별도 규칙을 쓴다. 첫 위험은 원본 시간을 유지하고, 두 번째 위험만
`7.0s` 늦춰 휠체어가 첫 재출발 뒤 실제로 접근하는 구간에 둔다. 두 Actor는 모두 `t=0`부터
지도 밖 진입선에서 같은 속도로 관측되며 episode 종료까지 track을 유지한다. 이는 공개
Ideal 합성 장면의 인과성을 맞춘 것이며 실제 초음파 센서의 선행 관측 가능성을 주장하지 않는다.

## 4. 횡단 실행 순서와 합격조건

```text
정지 유지
→ 방향성 예측 READY
→ 별도 재개 허가
→ 횡단 Actor가 기준 통로를 막는 동안 0.10m 초과 이탈
→ Actor와 0.08m 이상 거리로 crossing station 통과
→ 원 경로 재합류 0.50s 유지
→ 목표 도착·정지
```

좌·우를 구별하되 같은 방향 추월과 횡단 우회를 같은 사건명으로 세지 않는다. C++ DWB의 후보
217개, 후보당 41 자세, 2초 예측, 종단 정지, 안전거리, Capsule과 shared gate는 유지한다.

## 5. 다중 위험 실행 순서와 합격조건

```text
첫 위험에서 실제 정지
→ 첫 위험 해소 뒤 새 재개 허가
→ 실제 0.10m 이상 이동
→ 두 번째 위험에서 새 stop epoch로 다시 정지
→ 두 번째 위험 해소 뒤 새 재개 허가
→ 목표 도착·정지
```

하나의 긴 정지를 두 번으로 세거나 예전 재개 허가를 재사용하면 실패다. 이 단계는 횡단 1건의
실행 구조와 안전 경계를 먼저 확인한 뒤 진행한다.

다중 위험에서는 대체 우회 경로를 새로 만들지 않는다. 각 보호정지 뒤 현재 pose에서 같은
목적지까지의 기존 직선 경로를 새 `stop_epoch`와 새 reference session에 결박해 다시 발급한다.
첫 reference를 두 번째 정지 뒤 재사용하면 실패다.

## 6. 실행 순서

1. 원본 legacy 표적시험을 유지한다.
2. 파생 횡단 world·시간이동 witness와 독립 검증 시험을 추가한다.
3. C++ DWB 왼쪽 1건을 짧게 실행한다.
4. 성공한 뒤 오른쪽을 실행한다.
5. 횡단 회귀가 고정된 뒤 다중 위험 재정지 연결을 시작한다.
6. 마지막에만 영향권 회귀와 전체 회귀를 실행한다.

장시간 실행은 60초마다 현재 tick과 마지막 관찰 결과를 보고한다. hidden과 제품 경로분석
7단계는 시작하지 않는다.

## 7. 2026-08-16 공개 Ideal 결과

횡단 좌·우는 모두 방향성 예측 READY 뒤 tick `80`에 재개 허가를 받고 tick `81`에 움직였다.

| 방향 | 이탈 | 횡단 지점 통과 | 재합류 | 완료 | 최대 이탈 | 최소 Actor 여유 |
|---|---:|---:|---:|---:|---:|---:|
| 왼쪽 | 163 | 370 | 610 | 625 | 0.10m 초과 | 0.08m 이상 |
| 오른쪽 | 161 | 295 | 541 | 556 | 0.10m 초과 | 0.08m 이상 |

둘 다 C++ DWB 전체 코어를 사용했고 gate override와 hard failure는 `0`이었다. 횡단 사건은
같은 방향 Actor의 `추월`과 구별해 중립적인 `통과 사건`으로 기록한다.

다중 위험은 tick `44`에 첫 재개, tick `45`에 첫 움직임, tick `232`에 `stop_epoch=2`의
두 번째 실제 정지, tick `264`에 두 번째 새 reference·재개 허가, tick `490`에 목적지 완료를
확인했다. 두 정지 사이 실제 진행은 `1.7283m`, 최소 Actor 여유는 `0.1002m`, gate override와
hard failure는 `0`, controller/reference session은 `2개`였다.

이 결과는 합성 Ideal 관측의 공개 경로 기능 증거다. Normal·Stress, 카메라·가림, 실제 사람,
실물 차체, 50ms 자격, hidden, 제품 알고리즘 채택과 G1~G5 결정은 포함하지 않는다.

새 횡단·재정지 시험을 포함한 전체 실험실 회귀는 `916 passed`였고 실패·건너뜀은 `0`이었다.
