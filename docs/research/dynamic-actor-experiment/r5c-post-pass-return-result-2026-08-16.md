# R5-C 통과 후 원 경로 복귀 결과

## 결론

카메라 영역이 기존 `ActorTrack` 계약을 제공한다고 가정한 공개 Normal 횡단 장면에서,
사람을 지나쳤다는 검증 결과를 보존한 뒤 실제 정지하고 새 stop epoch로 원래 경로에
복귀하는 흐름을 연결했다.

- 왼쪽: 목적지 완료
- 오른쪽: 안전 위반 없이 목적지 판정선 바로 앞에서 보수 정지

따라서 통과 뒤 원 경로 복귀 구조는 동작했지만 좌·우 완주가 모두 증명된 것은 아니다.

## 변경

1. 통과 완료가 확인된 허가의 hash와 tick을 기록한다.
2. 이후 관측 상실 시 기존 허가·controller를 폐기하고 실제 정지한다.
3. 새 정지 번호와 현재 pose에 묶인 `FOLLOW_ORIGINAL` 경로를 만든다.
4. 목표는 새로 만들지 않고 기존 검증 횡단 경로의 terminal pose를 유지한다.
5. 원본 39초 이후의 진단 구간은 terminal Actor를 고정하지 않고 fresh EMPTY 관측으로
   연장한다. 이는 실제 카메라 성능 증거가 아니라 종단 제어 확인용 합성 입력이다.

안전거리 `0.08m`, DWB 후보·비용·rollout, Actor prediction, shared gate는 변경하지 않았다.

## 실행 결과

### 왼쪽, Normal, 1600 tick

- post-pass 증거: tick `632`
- 원 경로 복귀 첫 release: tick `680`
- 완료: tick `1580`
- 최종 pose: `(4.3189906, 2.3757077, -0.0372447)`
- 최소 Actor 여유: `0.5774769m`
- 최소 정적 여유: `0.3793126m`
- hard failure: `0`

### 오른쪽, Normal, 1800 tick

- post-pass 증거: tick `633`
- 원 경로 복귀 첫 release: tick `680`
- 완료: 없음
- 최종 pose: `(4.3200655, 2.3204622, 0.3768)`
- 기존 terminal까지 거리: 약 `0.0506m`
- 도착 허용값 `0.05m`보다 약 `0.0006m` 밖에서 더 안전한 이동 후보를 고르지 못함
- 최소 Actor 여유: `0.5969870m`
- 최소 정적 여유: `0.3786289m`
- hard failure: `0`

시간을 1800 tick까지 늘려도 오른쪽 최종 pose는 변하지 않았다. 다음 수정 대상은 안전값을
느슨하게 만드는 것이 아니라, terminal 바로 앞의 매우 짧은 잔여 이동을 DWB가 처리하지
못하는 원인이다.

## 증거 한계

- 실제 카메라·사람 검출·FOV·가림을 시험하지 않았다.
- Normal 한 프로필의 공개 합성 입력만 사용했다.
- 왼쪽 완료를 오른쪽 완료나 제품 안전으로 확대하지 않는다.
- formal R5-C/R6, hidden, 제품 알고리즘과 G1~G5는 시작하지 않았다.
