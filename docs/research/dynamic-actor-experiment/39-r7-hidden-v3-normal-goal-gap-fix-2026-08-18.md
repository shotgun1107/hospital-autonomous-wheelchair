# R7 hidden-v3 Normal 목표 직전 정지 수정 결과

## 1. 무엇이 문제였나

hidden-v3의 Normal 오른쪽 사례는 사람을 안전하게 통과하고 원 경로로 돌아왔지만,
목적지 `6.56 cm` 앞에서 멈췄다. 완료 제어는 목적지 `5 cm` 안에서만 시작하므로 남은
약 `1.56 cm`를 이동해야 했다.

이 구간에서 DWB의 정지 후보와 전진 후보 점수가 같았고, 기존 동률 규칙이 정지 후보를
선택했다. 실행시간 부족이 아니라 목적지 직전 제어 규칙의 빈틈이었다.

## 2. 무엇을 고쳤나

다음 조건을 모두 만족할 때만 같은 점수의 후보 중 전진 후보를 먼저 고르게 했다.

- 현재 구간이 원 경로를 따라 앞으로 가는 구간이다.
- 바로 다음 구간이 목적지 방향을 맞추는 회전 구간이다.
- 현재 위치가 그 구간 끝점에서 `0.10 m` 이내다.

충돌 거리, 안전 게이트, 목적지 완료 거리 `0.05 m`, Actor 예측과 정지 조건은 바꾸지
않았다. 이 변경은 목적지 바로 앞의 정지·전진 동률만 해소한다.

## 3. 확인 결과

소비된 hidden 입력은 최종 hidden으로 재사용하지 않고 공개 회귀 입력으로만 사용했다.

```text
observation seed: 4097001075006799098
tick limit: 1600
결과: completed
hard failure: 0
Actor 통과 확인 < 원 경로 재출발 < 목적지 완료: 통과
```

직접 영향 시험 결과:

```text
실패 입력 회귀: 1 passed in 53.89s
관련 DWB·구간 실행·재정지·R7 시험: 39 passed in 111.44s
```

## 4. 아직 남은 것

Stress 실패는 이 코드 문제와 다르다. 현재 시스템은 서로 다른 정상 관측 11개를 확인하면
Stress에서도 출발할 수 있지만, hidden-v3 시험은 80초 동안 한 번도 움직이지 않기를
요구했다. 다음 hidden 전에 공개 명세에서 아래 중 하나를 선택해야 한다.

1. Stress를 항상 운행 금지로 정의한다.
2. Stress도 충분한 정상 관측 뒤 출발을 허용하고, 관측이 다시 끊기면 즉시 안전정지하는지
   평가한다.

현재 동작과 맞는 기본안은 2번이다. hidden-v3 판정은 `FAIL`로 그대로 보존하며, 이번 수정
뒤 새 hidden은 실행하지 않았다. 새 hidden 전에 전체 회귀와 R7 50ms 자격을 다시 확인해야
한다.
