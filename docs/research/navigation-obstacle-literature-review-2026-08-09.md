# 병원 자율휠체어 경로·장애물 대응 폭넓은 문헌 조사

- 조사일: 2026-08-09
- 상태: 비권위 조사 자료
- 기준선: [경로 기능 1단계 기준선](../product/path-planning-baseline.md)
- 목적: 2단계 추상 시나리오를 만들기 전에 직접 선행사례와 인접 분야의 유용한 개념·시험법을 폭넓게 수집한다.

이 문서는 제품 요구사항, 센서, 좌표계, SLAM, 경로 알고리즘을 채택하지 않는다. 실제 운영, 현장·임상 실증, 연구 프로토타입, 시뮬레이션, 표준과 기업 발표를 구분해 해석한다.

## 조사 방법과 한계

이번 조사는 체계적 문헌고찰이 아니라 범위를 넓게 탐색하는 스코핑 조사다. 다음 순서로 근거를 우선했다.

1. 병원·정부·표준기관의 공식 자료
2. 원 논문과 임상·현장 연구
3. 실제 배치 사례를 설명하는 기업 공식 자료
4. 공식 소프트웨어 문서와 인접 분야의 대표 논문

자율휠체어 외에도 병원 물류 AMR, 공항 이동서비스, 사회적 내비게이션, 창고 AGV, 자동차 시나리오 시험, 소프트웨어 조합시험, 로봇 시뮬레이션을 조사했다. 공개 자료만으로 실제 운영 여부를 입증할 수 없는 경우에는 실증, 연구 또는 발표로만 표시했다.

## 핵심 판정

1. 프로젝트 아이디어와 매우 가까운 선행 시스템이 이미 있다. 특히 2021년 Connected Driverless Wheelchair는 병원 정보시스템 요청, 환자 ID 기반 위치 조회, 빈 차량의 환자 위치 이동, 승객 운송, 하차, 대기 지점 복귀를 하나의 흐름으로 구현했다.
2. 실제 운영 중인 WHILL 계열 서비스는 대체로 `사전 지도 + 등록 승차장·목적지 + 검증된 제한 경로 + 장애물 앞 감속·정지 + 무인 자동 복귀` 방식이다. 임의 위치에서 택시처럼 부르는 운영은 공개 근거로 확인되지 않았다.
3. 국내에도 2020년 환자이송 자율주행 로봇 사업과 2024년 실시간 모니터링 자율주행 휠체어 환자이송 규제특례가 확인된다. 따라서 `국내에 유사 아이디어가 없다`는 주장은 사용할 수 없다.
4. `정적 장애물 / 동적 장애물`은 좋은 첫 분류지만 그것만으로 대응을 결정하기에는 부족하다. 실제 행동은 지속시간, 경로 차단 정도, 대체 통로, 국소 통과 공간, 위치·인식 신뢰도, 공간 형태, 사람의 우선권에 의해 달라진다.
5. 실제 상용·병원 사례는 보수적으로 정지하는 경우가 많다. 자유 우회, 군중 예측, 복잡한 상호 양보는 주로 연구 범위다.
6. `충돌하지 않음`만으로 성공을 정의하면 부족하다. 목적지 도달, 최소 이격거리, 급정지·반복정지, 승차감, 사람이 위험하게 비켜서지 않았는지, 자동 복구 실패 시 안전한 인계까지 봐야 한다.
7. 가능한 모든 현실 장면을 하나씩 열거할 필요는 없다. 타 분야에서 쓰는 `기능 시나리오 → 조건 범위가 있는 논리 시나리오 → 수치가 정해진 구체 시험` 구조와 조합시험을 적용하는 편이 누락을 줄이고 실행 가능한 시험 수를 만든다.

## 병원·공항 운영에서 확인된 공통 구조

- 등록 지점과 제한 경로를 먼저 검증한 뒤 서비스를 연다.
- 승객이 내린 뒤 차량이 승차장, 대기 지점 또는 충전 지점으로 돌아온다.
- 자동화 경계 밖에는 탑승 보조, 하차 보조, 적재·하역, 문·엘리베이터 지원, 수동 회수가 남는다.
- 지도상 길이 있어도 공사, 문, 침대·카트, 혼잡, 통신 음영, 위치추정 저하 때문에 실행하지 못할 수 있다.
- 실제 운영은 기술 데모보다 이용 자격, 인계, 알림, 실패 복구, 시설 변경 관리의 영향을 크게 받는다.

## 원 분야 밖에서 가져올 수 있는 핵심 교훈

### 사회적 내비게이션

사람은 단순히 속도를 가진 장애물이 아니다. 사람은 로봇의 움직임을 보고 양보하거나 멈추고, 때로는 로봇 때문에 위험한 공간으로 밀려난다. 따라서 `사람이 비켜서 로봇이 통과함`을 곧바로 성공으로 기록하면 안 된다.

대표 상황은 정면 접근, 횡단, 사람의 추월, 로봇의 추월, 좁은 출입구, 좁은 복도, 사각 모퉁이, 교차로, 군집이다. 안전 외에도 편안함, 의도 가독성, 예의, 사람 경로 방해 정도를 본다.

### 창고 AGV와 다중 로봇

좁은 통로는 단순한 자유공간이 아니라 한 번에 한 방향 또는 한 차량만 점유하는 공유 자원이 될 수 있다. 양쪽이 서로 멈추면 충돌은 없지만 임무도 끝나지 않는 교착 상태가 된다. 현재 프로젝트는 한 대만 대상으로 하지만, 다른 자율휠체어나 병상·카트와의 대치는 이 개념을 이용해 추상화할 수 있다.

### 자동차·자율시스템 시험

PEGASUS 방식은 시나리오를 다음 세 수준으로 나눈다.

1. 기능 시나리오: 자연어로 `복도에서 사람이 횡단한다`처럼 상황의 의미를 적는다.
2. 논리 시나리오: 속도, 거리, 통로 폭, 등장 시점 등을 값의 범위로 둔다.
3. 구체 시나리오: 각 값을 하나로 정해 실제 시험 한 건을 만든다.

이 구조를 적용하면 현재 2단계에서는 기능 시나리오를 만들고, 하드웨어·센서가 정해진 뒤 논리 범위를 정하며, Python·Unity·실물 시험에서 구체 사례로 바꿀 수 있다.

모든 값의 전체 데카르트 곱을 시험하는 대신 pairwise 또는 t-way 조합으로 대표 조합을 만들고, 안전상 위험한 조합은 별도 강제 시험으로 둔다.

### 표준과 성능시험

- [ISO 18646-2:2024](https://www.iso.org/standard/82643.html)은 서비스로봇 항법의 위치·경로·장애물 검출·회피 성능시험을 다룬다. 안전 인증과 동일하지 않다.
- [ISO 13482:2014](https://www.iso.org/standard/53820.html)은 개인 돌봄 로봇의 사람 관련 위험을 다루지만 의료기기는 제외한다.
- [ISO 3691-4:2023](https://www.iso.org/standard/83545.html)은 산업용 무인차량과 운영구역의 안전을 다룬다. 공공 병원 환경에 직접 적용하는 규격은 아니지만 운영구역 조건을 함께 보라는 교훈을 준다.
- [ASTM F3244-21](https://store.astm.org/f3244-21.html)은 제한 공간에서의 항법을 구현 방식과 독립적으로 시험한다.
- [ASTM F3381-19](https://store.astm.org/f3381-19.html)은 정적 장애물의 특성을 재현 가능하게 기록하도록 한다.
- [ISO/AWI 7176-34](https://www.iso.org/standard/93942.html)는 자동주행 기능이 있는 로봇 휠체어의 등급과 시험법을 마련하는 2026년 신규 작업 항목이다. 조사일 현재 개발 중이며 발행된 국제표준이 아니다.

이 표준들은 축소형 대회 작품의 인증 요구가 아니다. 다만 시험 항목과 용어를 정할 때 참고할 수 있다.

## 문헌에서 귀납한 장애물·경로 상황의 축

아래는 채택된 제품 요구가 아니라, 다음 단계에서 누락을 줄이기 위한 분류 후보이다.

| 축 | 후보 값 |
|---|---|
| 운행 단계 | 출발 전, 빈차 픽업 이동, 탑승 대기·탑승 중, 승객 이동, 하차 대기·하차 중, 자동 복귀 |
| 경로 영향 | 경로와 무관, 보호영역 침범, 일부 폭 점유, 현재 구간 전체 차단, 전체 목적지 도달 불가 |
| 시간성 | 순간, 대기 한도 안에 해소, 한도 뒤 해소, 지속, 해소 시각 불명 |
| 운동 형태 | 정지, 일시정지, 정면 접근, 횡단, 같은 방향, 추월·피추월, 갑작스러운 진입, 군집, 불확실 |
| 공간 형태 | 열린 공간, 넓은 복도, 단선형 좁은 복도, 출입구, 교차로, 사각 코너, 막다른 길, 목적지 근처 |
| 대안 | 기존 경로 유지, 감속·관찰, 정지·대기, 국소 우회 후 복귀, 전체 경로 재선택, 안전 후진, 직원 지원, 대안 없음 |
| 신뢰도 | 판단 확실, 센서 간 불일치, 지도와 실제 불일치, 위치 불확실, 통신·센서 고장 |
| 사회적 우선권 | 일반 사람 우선, 환자·이동약자, 의료진·병상, 긴급 통행, 다른 로봇, 우선권 미정 |
| 최종 판정 | 정상 성공, 대기 후 성공, 우회 성공, 안전정지, 자동복구 성공, 교착, 임무 불가, 충돌·안전 실패 |

중요한 점은 정적·동적 분류를 버리는 것이 아니라 첫 축으로 유지하되, 다음 질문을 교차시키는 것이다.

- 예정 경로와 실제로 충돌하는가?
- 잠시 기다리면 사라질 가능성이 있는가?
- 허용된 공간 안에서 국소적으로 지나갈 수 있는가?
- 현재 통로만 막혔고 다른 전체 경로는 있는가?
- 위치와 장애물 판단을 신뢰할 수 있는가?
- 멈춘 뒤 다시 출발해도 되는 조건이 명확한가?
- 안전하게 기다리거나 후진할 장소가 있는가?

## 문헌 기반 기능 시나리오 후보

다음 목록은 2단계 검토 후보이며 아직 승인된 시나리오가 아니다.

1. 장애물 없는 정상 이동
2. 경로 밖 장애물로 인해 운행에 영향이 없는 경우
3. 통로 일부를 차지하지만 안전한 여유가 있는 정지 장애물
4. 현재 통로 전체를 막고 다른 등록 경로가 있는 정지 장애물
5. 허용된 모든 경로가 막힌 정지 장애물
6. 정면에서 접근하는 사람 또는 이동체
7. 경로를 횡단하는 사람 또는 이동체
8. 같은 방향의 느린 이동체와 추월·피추월
9. 움직이던 사람이 통로에서 멈추고 다시 움직이는 경우
10. 좁은 출입구·복도에서 서로 양보하며 교착할 수 있는 경우
11. 사각 모퉁이에서 갑자기 나타나는 이동체
12. 정적 장애물과 이동체가 함께 있는 복합 상황
13. 목적지 또는 출발 지점이 점유된 경우
14. 지도상 길은 있으나 지도·위치·센서 판단을 신뢰할 수 없는 경우
15. 정지 뒤 장애물이 사라져 재출발하는 경우
16. 유한한 대기·복구 뒤에도 해결되지 않아 사람 지원이 필요한 경우

## Python·Unity·실물의 역할 분리

두 시뮬레이션 구상은 서로 대체 관계가 아니라 검증 층이 다르다.

|---|---|---|
| Python 배열·격자 | 시작·목표 도달성, 경로 연결성, 정적 차단, 주행 중 점유 변경, 대기와 재계획의 논리, 대량 조합·회귀시험 | 실제 회전반경, 제동, 마찰, 센서 오차, 사람 체감 |

| 축소 실물 | 센서 지연, 바퀴 미끄러짐, 제동거리, 실제 외곽선과 회전, 통신 지연, 비상정지 | 실제 환자 탑승 안전성과 의료기기 수준 인증 |

## 성능 지표 후보

2024 병원 AMR 벤치마크와 사회적 내비게이션 연구를 합치면 다음 지표군이 유용하다. 수치와 합격선은 아직 정하지 않는다.

- 안전: 충돌·접촉 수, 최소 장애물 거리, 정지 명령 뒤 추가 이동, 허용 영역 이탈
- 임무: 목적지 도달 성공률, 안전정지 성공, 무경로·불확실성의 올바른 보고, 수동 인계 성공
- 효율: 완료시간, 경로 길이, 대기시간, 재계획 횟수, 교착 지속시간
- 정확도: 목표 위치·방향 오차, 계획 경로와 실제 경로의 편차
- 승차감: 급정지, 급가속, 불필요한 반복 정지·재출발
- 사회성: 사람과의 최소 거리, 사람 경로 방해, 사람이 위험하게 양보했는지, 로봇 행동의 예측 가능성
- 복구: 장애물 소실 뒤 올바른 재출발, 복구 횟수 제한, 실패 뒤 자동 재출발 금지, 지원 요청 전달

## 프로젝트에 반영할 수 있는 연구 결론

### 유지할 것

- 알려진 지도, 등록 지점, 단층 통제 공간, 한 대의 축소 휠체어라는 1단계 기준선은 실제 운영 사례와 잘 맞는다.
- `충돌 가능 장애물 감지 → 먼저 안전정지 → 대체 이동 판단 → 불가능하거나 불확실하면 정지 유지` 원칙은 상용·연구의 보수적 실패행동과 부합한다.
- 정적·동적 장애물 구분은 2단계의 출발점으로 유용하다.

### 수정할 주장

- `국내에 유사 기획이 없다`는 주장은 폐기한다.
- `자율주행 휠체어 자체`를 독창성으로 주장하지 않는다.
- 공개된 WHILL 운영을 `환자 임의 위치 호출`로 확대 해석하지 않는다.

### 가능한 차별화 방향

대회에서 주장할 수 있는 차별성 후보는 다음 기능을 축소형 완성 시스템으로 통합하고 반복 검증하는 데 있다.

- 의료진 예약과 환자 직접 호출
- 등록 승차장으로의 빈차 배차
- 탑승·운행·하차·자동복귀의 하나의 미션 흐름
- 정적·동적·복합 장애물에 대한 명시적 정지·대기·대체 이동·실패 처리
- 환자·의료진·관제에 진행 상태와 정지 이유 전달
- Python → Unity → 축소 실물로 같은 기능 시나리오를 단계적으로 검증

이는 조사에서 도출한 차별화 후보일 뿐, 팀이 승인한 최종 홍보 문구는 아니다.

문헌 조사는 기술 선택 대신 다음 질문을 2단계에 넘긴다.
