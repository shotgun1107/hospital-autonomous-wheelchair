# 대회 구현 범위

> 세부 MUST·SHOULD·OUT OF SCOPE는 팀 검토용 후보 목록이다. 현재 확정 기준은 아니며, 우선 기준은 [프로젝트 큰 틀 기준선](big-picture.md)이다.

## MUST 후보 — 팀 합의 전

- 인형이 탑승하는 한 대의 축소형 휠체어 하드웨어
- 저속 구동, 방향 제어와 물리 비상정지
- 대기 위치, 등록된 승차 지점과 목적지를 잇는 통제된 평면 경로
- 선택한 장애물 대응 방식을 보여줄 수 있는 통제된 시연 경로
- 의료진 예약과 승차 지점 직접 호출
- 두 요청 흐름 모두 스스로 승하차할 수 있는 비응급 환자를 대상으로 하는 서비스 가정
- 목적지 도착 목표시각을 입력하는 의료진 예약
- 환자 탑승 확인 전까지의 의료진 예약 목적지·도착 목표시각 수정
- 환자 탑승 확인 전까지의 의료진 예약 취소
- 미시작 요청 충돌 시 의료진 예약 기본 우선과 의료진의 순서 변경 운영 흐름
- 사용 중 요청의 대기열 등록, 대기 순번과 예상 대기시간 표시
- QR 탑승 확인 전까지의 환자 요청 취소
- 실제 서비스용 개인 스마트폰 웹과 대회 MVP용 승차장 태블릿·키오스크
- 빈 휠체어의 승차 지점 이동과 고정 모형 QR을 이용한 MVP 탑승 확인
- 센서 자동 하차 확인과 환자 버튼·의료진 확인 fallback
- 승객의 `정지·도움 요청`, 즉시 정지, 현장 알림음·화면 표시와 의료진 웹 알림
- 환자 화면의 배정·예상 도착시간·운행 상태·취소·도움 요청과 병원 지도의 예정 경로·의미적 위치
- 의료진 충돌 요청 목록의 환자 ID·목적지 표시
- 실제 서비스의 병원 팔찌·환자 QR과 앱 QR 구분, 대회 MVP의 고정 모형 QR
- QR 불일치 시 목적지 운행 금지와 담당 의료진 웹 알림
- 예약 환자 부재의 의료진 보고 후 자동 복귀
- 직접 호출 환자 부재 시 기본 3분 대기·소리 알림·자동 복귀
- 탑승 전 취소된 빈 휠체어의 다음 요청 재배정 또는 자동 복귀
- 출발 전 배터리 상태 확인과 운행 중 일반 저전력의 현재 운행 완료 후 복귀
- 즉시 운행을 계속할 수 없는 임계 전원 문제의 안전정지
- 목적지 도착 지연 예상의 의료진 알림과 운행 계속
- 장애물을 감지하면 다른 이동을 결정하기 전에 수행하는 로컬 안전정지
- 움직이는 사람을 포함한 장애물 상황의 공통 대응
- 전체 대체 경로 선택 또는 제한적 현재 경로 수정 중 최소 하나를 이용한 장애물 대응
- 대체 이동 방법이 없으면 `BLOCKED`로 정지
- 목적지 도착 후 대기 위치 자동 복귀
- 경로·통신 상실 시 정지와 수동 회수
- 단일 웹, 서버, 로봇 제어, 펌웨어와 하드웨어의 종단 연동
- 이벤트 로그와 반복 시험 증거

## SHOULD 후보 — 팀 합의 전

- 전체 대체 경로 선택과 제한적 현재 경로 수정을 모두 포함하는 시연
- 카메라를 이용한 장애물 유형 표시
- 구간 진행률과 PWA 설치 경험

전체 대체 경로 선택과 장애물 주변의 짧은 현재 경로 수정은 서로 다른 기능으로 본다. MVP에는 둘 중 최소 하나를 포함하되 무엇을 선택할지는 아직 정하지 않는다. 구체적인 지도 구조와 계산 방식도 아직 정하지 않는다.

## OUT OF SCOPE

- 실제 환자 또는 성인 탑승
- 의료기기 수준의 안전성·임상 적용성 주장
- 실제 병원 EMR·HIS·EHR 연동
- 실제 병원 전체 규모의 미지 환경 자율주행
- 움직이는 사람의 궤적을 예측해 비집고 통과하는 동적 회피
- 사전에 허용되지 않은 공간의 임의 탐색
- 복수 휠체어 운영과 플릿 최적화
- 엘리베이터와 다층 이동
- 관제 화면의 정밀 연속 좌표
- 별도 환자 네이티브 앱과 별도 의료진 네이티브 앱
- 실제 생체신호 측정·위급 판단과 건강관리 모듈 연동
- 환자별 접근성 프로필과 청소·충전·정비의 전체 운영 상태 관리

## 범위 원칙

자율주행 휠체어 종단 시스템이라는 원래 정체성을 유지한다. 의료진의 목적지 도착 목표시각 예약과 환자 직접 호출은 두 문제를 함께 해결하는 기능이며, 대회 시연은 환자 직접 호출을 중심으로 구성한다.

이 문서는 기능 범위만 확정한다. 위치 추정, 지도 표현, 경로 계산, 센서와 제어 방식은 큰 시스템 구성이 완료되기 전에는 확정하지 않는다.
