# 핵심 사용 시나리오

> 큰 두 호출 흐름 외의 예외 처리는 팀 합의 전 브레인스토밍 초안이다. 현재 단계의 우선 기준은 [프로젝트 큰 틀 기준선](big-picture.md)이다.

## 1. 의료진 예약 호출

1. 병원 관계자가 가상 환자 ID, 목적지 도착 목표시각, 등록된 승차 지점과 목적지를 입력한다.
2. 시스템이 한 대의 휠체어로 해당 이동을 처리할 수 있는지 판단한다.
3. 기존의 미시작 예약이나 직접 호출과 충돌하면 의료진 예약을 기본 우선으로 제시하고, 의료진이 필요하면 미시작 요청의 처리 순서를 바꾼다. QR 탑승 확인 뒤 시작된 승객 운행은 중단하지 않는다.
4. 바로 처리하지 못하는 요청은 대기열에 넣고 대기 순번과 예상 대기시간을 표시한다.
5. 이동 차례가 되면 빈 휠체어가 대기 위치에서 승차 지점으로 이동한다.
6. 대회 MVP에서는 승차 지점에서 고정된 모형 QR로 대상 미션을 확인한 뒤 목적지 운행을 시작한다.
7. 목적지에 도착해 운행을 마치면 빈 휠체어가 대기 위치로 자동 복귀한다.

QR이 현재 미션과 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.

목적지 도착 목표시각을 만족시키기 위해 언제 출발시킬지 계산하는 구체적인 방법은 이후 설계에서 정한다.

의료진은 환자의 탑승 확인 전까지 자신이 만든 예약의 목적지와 도착 목표시각을 수정할 수 있다. 탑승 확인 뒤 시작된 승객 운행의 목적지는 이 정책으로 바꾸지 않는다.

의료진이 탑승 확인 전에 예약을 취소하면, 승객이 없는 휠체어는 다음 요청이 있을 경우 해당 승차 지점으로 재배정되고 없으면 대기 위치로 복귀한다.

## 2. 환자 직접 호출

1. 실제 서비스에서는 환자가 개인 스마트폰 웹에서 호출하고, 대회 MVP에서는 승차장 태블릿·키오스크에서 목적지를 선택한다.
2. 직접 호출도 예약 호출과 동일한 미션 객체를 생성한다.
3. 휠체어가 사용 중이면 요청을 대기열에 등록하고 대기 순번과 예상 대기시간을 표시한다. 환자는 휠체어가 승차 지점으로 이동 중이더라도 QR 탑승 확인 전까지 취소할 수 있다.
4. 예약과 충돌하면 미시작 의료진 예약을 기본 우선 처리하되, 의료진은 필요하면 미시작 요청의 순서를 바꿀 수 있다.
5. 이동 차례가 되면 빈 휠체어가 승차 지점으로 이동한다.
6. 대회 MVP에서는 환자가 고정된 모형 QR로 미션을 확인하면 목적지 운행을 시작한다.
7. 목적지 도착 후 빈 휠체어는 대기 위치로 자동 복귀한다.

QR이 현재 미션과 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.

## 3. 환자 부재, 지연과 대기 취소

- 의료진 예약의 환자가 승차 지점에 없으면 의료진에게 부재를 보고하고 요청을 종료한 뒤 대기 위치로 자동 복귀한다.
- 승차장 직접 호출의 환자가 없으면 기본 3분 동안 기다리고 소리로 호출한다. 계속 나타나지 않으면 요청을 종료하고 대기 위치로 자동 복귀한다. 대회 시연에서는 대기시간을 10초로 축약한다.
- 목적지 도착 목표시각 지연이 예상되면 의료진에게 알리고 운행은 계속한다.
- 환자가 직접 호출을 취소하거나 의료진이 예약을 탑승 확인 전에 취소하면, 승객이 없는 휠체어는 처리할 다음 요청이 있을 경우 그 승차 지점으로 재배정되고 없으면 대기 위치로 복귀한다.

소리 알림은 단순 알림음과 화면 표시를 사용하며, 반복 횟수와 간격은 이후에 결정한다.

## 4. 승객의 정지·도움 요청

1. 승객 운행 중 환자가 화면의 `정지·도움 요청`을 누른다.
2. 휠체어가 즉시 정지하고 현장 알림음과 화면으로 도움 요청 상태를 표시한다.
3. 운영 서버가 환자 정보에 등록된 담당 의료진·담당 병동 알림 대상의 화면에 환자 ID, 미션과 의미적 위치를 포함한 도움 요청을 알린다.
4. 의료진이 상황을 확인할 때까지 자동으로 다시 출발하지 않는다.
5. 의료진의 확인·재개·회수 세부 절차는 이후에 결정한다.

## 5. 장애물 발생과 대체 이동

1. 로봇이 주어진 병원 지도에 따라 목적지로 이동한다.
2. 진행을 방해하는 장애물을 감지하면 먼저 안전하게 정지한다.
3. 기존 미션과 목적지는 유지한다.
4. 시스템은 주어진 지도와 허용된 이동 영역 안에서 다른 이동 방법이 있는지 판단한다.
5. 안전한 대체 이동 방법이 있으면 같은 미션을 계속한다.
6. 찾지 못하면 `BLOCKED` 상태와 이유를 표시하고 사람이 개입할 때까지 움직이지 않는다.

움직이는 사람도 별도 서비스가 아니라 장애물 상황으로 취급한다. 먼저 정지한 뒤 기다릴지 다른 이동 방법을 찾을지는 당시 상황과 허용된 장애 대응 범위에 따라 판단한다.

대체 경로를 표현하고 계산하는 방식, 현재 위치를 판단하는 방식과 로봇 내부 상태는 이후 기술 설계에서 결정한다.

## 6. 제한적 현재 경로 수정 후보

장애물 주변의 허용 공간 안에서 짧게 경로를 수정한 뒤 원래 진행 방향으로 복귀하는 기능도 후보로 둔다. 이 기능을 최종 시연에 포함할지, 어떤 환경에서 허용할지와 어떤 기술을 사용할지는 아직 결정하지 않았다.

## 7. 실패와 수동 회수

- 경로 상실, 통신 끊김, 근접 보호정지 또는 물리 비상정지가 발생하면 모터 출력을 안전하게 차단한다.
- 이런 안전정지는 원인이 해소돼도 자동 재출발하지 않는다. 계획 거리에서 수행하는 정상적인 장애 구간 재탐색과 구분한다.
- 복구할 수 없으면 미션을 중단하고 `RECOVERY_REQUIRED`를 기록한 뒤 사람이 모형을 회수한다.

## 8. 자동 복귀

1. 목적지에서 센서로 하차 완료를 자동 확인한다.
2. 자동 확인이 불확실하면 환자가 `하차 완료` 버튼을 누른다.
3. 버튼으로도 확인할 수 없으면 의료진이 하차 완료를 확인한다.
4. 하차 완료가 확인되면 현재 미션의 승객 운행을 종료한다.
5. 빈 휠체어가 대기 위치로 복귀한다.
6. 복귀 중에도 장애물과 실패에 대한 동일한 정지 원칙을 적용한다.

센서 종류와 자동 확인 판정 기준은 기술 설계에서 결정한다.

## 9. 배터리 부족

1. 새 미션을 출발하기 전에 배터리 상태로 운행 가능 여부를 판단한다.
2. 출발 조건을 만족하지 못하면 새 미션을 시작하지 않는다.
3. 승객 운행 중 일반 저전력이 확인되면 현재 목적지까지 운행을 마친다.
4. 하차 완료 후 새 미션을 받지 않고 대기 위치로 복귀한다.
5. 즉시 운행을 계속할 수 없는 임계 전원 문제는 일반 저전력과 구분해 안전정지한다.

일반 저전력과 임계 전원의 구체적인 기준은 기술 설계에서 결정한다.
