# 프로젝트 개념

> 세부 서비스 정책을 포함한 개인 브레인스토밍 초안이다. 현재 단계의 우선 기준은 [프로젝트 큰 틀 기준선](big-picture.md)이며, 팀 합의 전에는 구현 기준으로 사용하지 않는다.

## 문제

병원에서는 거동이 불편한 환자가 검사실, 진료실, 병실 등으로 이동해야 한다. 이 과정에서 의료진의 동행·운반 부담이 발생하거나 환자가 필요한 시간에 이동수단을 확보하기 어렵다.

## 제안

등록된 승차 지점에서 사용할 수 있는 자율주행 휠체어와 다음 두 요청 흐름을 하나의 미션 체계로 연결한다.

1. 병원 관계자가 환자의 예정 이동을 등록하는 예약 호출
2. 환자가 승차 지점에서 목적지를 선택하는 직접 호출

프로젝트는 의료진의 이동 업무 부담 감소와 환자의 이동 자율성 향상을 함께 목표로 한다. 작품의 중심은 예약 소프트웨어만도, 단순 주행 장치만도 아니다. 호출·예약·대기·배차·QR 확인·물리 이동·실패 처리·자동 복귀가 동일한 미션 흐름으로 이어지는 축소형 종단 시스템이다.

## 확정된 서비스 정책

- 의료진이 입력하는 시간은 환자의 목적지 도착 목표시각이다.
- 미시작 예약과 직접 호출이 충돌하면 의료진 예약을 기본 우선 처리하고, 의료진은 필요하면 처리 순서를 바꿀 수 있다. 이미 탑승해 이동 중인 환자는 중단하지 않는다.
- 의료진은 환자의 탑승 확인 전까지 자신이 만든 예약의 목적지와 도착 목표시각을 수정할 수 있다.
- 의료진은 환자의 탑승 확인 전까지 자신이 만든 예약을 취소할 수 있다.
- 사용 중 새 요청은 대기열에 넣고 대기 순번과 예상 대기시간을 보여준다.
- 환자는 QR 탑승 확인 전까지 자신의 요청을 취소할 수 있다.
- 실제 서비스의 환자 인터페이스는 개인 스마트폰 웹을 목표로 한다.
- 대회 MVP의 환자 인터페이스는 승차장 태블릿·키오스크로 구성한다.
- 대회 MVP에서는 고정된 모형 QR로 탑승 확인 흐름을 보여준다.
- 예약 환자 부재는 의료진에게 보고한 뒤 자동 복귀한다.
- 직접 호출 환자 부재는 기본 3분 대기·소리 알림 후 자동 복귀하며, 대회 시연에서는 10초로 축약한다.
- 목적지 도착 목표시각 지연이 예상되면 의료진에게 알리되 운행은 계속한다.
- 목적지 운행을 마친 빈 휠체어는 대기 위치로 자동 복귀한다.
- 하차 완료는 센서 자동 확인을 우선하고, 불확실하면 환자 버튼과 의료진 확인을 차례로 사용한다.
- 승객 운행 중 환자의 `정지·도움 요청`은 즉시 정지, 현장 알림음·화면 표시와 등록된 담당 의료진·담당 병동 알림 대상으로의 통보로 이어지며 의료진 확인 전에는 자동 재출발하지 않는다.
- 환자 화면에는 배정·예상 도착시간·운행 상태·취소·도움 요청과 병원 지도의 예정 경로·의미적 위치를 함께 보여준다.
- 실제 서비스의 예약 환자는 병원 팔찌·환자 QR, 직접 호출 환자는 앱 QR로 미션을 확인한다.
- QR이 미션과 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.
- 탑승 전 취소된 빈 휠체어는 다음 요청이 있으면 재배정하고 없으면 대기 위치로 복귀한다.
- 새 미션 출발 전 배터리 상태를 확인하고, 운행 중 일반 저전력이 확인되면 현재 승객 운행을 마친 뒤 복귀한다.
- 대회 시연은 환자 직접 호출 흐름을 중심으로 구성한다.

## 대회용 프로토타입

- 한 대의 축소형 자율주행 휠체어 하드웨어를 제작한다.
- 영유아보다 조금 작은 인형을 시험 대역으로 사용한다.
- 한 층의 통제된 모형 병원과 등록된 승차 지점을 사용한다.
- 사전에 주어진 병원 지도를 이용해 승차 지점과 목적지 사이를 이동한다.
- 장애물을 만나면 먼저 정지하고 대체 경로 또는 제한적 경로 수정 가능성을 판단한다.
- 대체 이동 방법 없음, 경로 상실, 통신 끊김과 비상정지를 정상 운행과 함께 검증한다.
- 고정 장애물과 움직이는 사람을 모두 장애물 상황으로 다루되 먼저 정지한다.
- 환자 직접 호출부터 QR 확인, 목적지 도착과 자동 복귀까지를 중심 시연으로 사용한다.

지도 표현, 위치 추정, 장애물 인식과 경로 계산의 구체적인 기술은 제품 기획과 큰 시스템 구성이 확정된 뒤 설계한다.

## 검증 범위의 경계

이 결과물은 실제 환자 탑승형 의료기기가 아니라 축소형 운영·제어 POC다. 다음 사항을 검증했다고 주장하지 않는다.

- 성인 탑승 하중, 승차감 또는 전복 안정성
- 실제 병원 혼잡 환경에서의 안전성
- 임상 서비스 적합성
- 의료기기 법규·인증 적합성

목표 서비스 사용자는 독립 승하차가 가능한 비응급 환자지만, 대회 시험에는 실제 사람을 태우지 않는다.

환자별 접근성 설정은 실제 서비스의 후속 설계 대상으로 두고 대회 MVP에서는 개인별 프로필을 구현하지 않는다. 청소·충전·정비 운영 관리도 대회 MVP에는 포함하지 않으며, 실제 서비스의 일반 환자 화면에는 내부 운영 사유 대신 이용 가능 여부와 예상 대기시간만 제공한다.

## 차별화 후보

자율주행 휠체어 자체의 최초성을 주장하지 않는다. 의료진의 목적지 도착 목표시각 예약, 환자 직접 호출, 대기열·예상 대기시간, QR 확인, 장애 상황의 대체 이동과 자동 복귀를 하나의 미션 흐름으로 연결하는 점을 통합 차별점 후보로 둔다.

건강관리 모듈이나 기존 환자 모니터링 시스템의 위급 신호를 연동해 자동 정지·담당 의료진·담당 병동 긴급 알림으로 이어지는 기능은 장기 확장 아이디어로만 둔다. 대회 MVP에는 포함하지 않으며 실제 생체신호 측정과 위급 판단을 검증했다고 주장하지 않는다.
