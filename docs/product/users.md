# 사용자

> 사용자 세부 행동은 팀 합의 전 초안이다. 현재 단계의 우선 기준은 [프로젝트 큰 틀 기준선](big-picture.md)이다.

## 목표 서비스 사용자: 환자

- 비응급 상황에서 서비스를 이용한다.
- 등록된 승차 지점까지 접근할 수 있다.
- 의료진 예약과 직접 호출 모두 보호자나 의료진의 직접 승하차 도움 없이 스스로 승하차할 수 있다고 가정한다.
- 실제 서비스에서는 개인 스마트폰 웹에서 호출하고 목적지를 선택한다.
- 대회 MVP에서는 승차장 태블릿·키오스크에서 직접 호출한다.
- 실제 서비스에서는 의료진 예약 환자는 병원 팔찌·환자 QR, 직접 호출 환자는 앱 QR로 배정된 미션을 확인한 뒤 탑승한다.
- 휠체어가 사용 중이면 대기 순번과 예상 대기시간을 확인한다.
- 휠체어가 승차 지점으로 이동 중이더라도 QR 탑승 확인 전까지 자신의 요청을 취소할 수 있다.
- 목적지에서 자동 하차 확인이 불확실하면 `하차 완료` 버튼으로 확인할 수 있다.
- 환자 화면에서 배정 여부, 예상 도착시간, 운행 상태와 병원 지도의 예정 경로·의미적 위치를 확인한다.
- 실제 서비스에서는 이용 가능 여부와 예상 대기시간을 확인하되 청소·정비 같은 내부 운영 사유는 기본적으로 보지 않는다.
- 승객 운행 중에는 `정지·도움 요청`을 사용할 수 있으며, 의료진 확인 전에는 자동으로 다시 출발하지 않는다.
- 환자 정보에는 도움 요청과 QR 불일치를 통보할 담당 의료진 또는 담당 병동 알림 대상이 연결돼 있다고 가정한다.

실제 서비스에서는 탑승 가능 조건과 제외 조건을 별도로 검증해야 한다. 대회 프로토타입만으로 실제 환자 사용 가능성을 주장하지 않는다.

## 운영 사용자: 병원 관계자

- 간호사, 의사 등 환자의 목적지 도착 목표시각, 승차 지점과 목적지를 등록하고 상태를 확인한다.
- 미시작 예약과 환자 직접 호출이 충돌하면 의료진 예약이 기본 우선으로 제시되며, 필요하면 처리 순서를 바꾼다.
- 충돌 요청 목록의 기본 정보로 환자 ID와 목적지를 확인한다.
- 환자의 탑승 확인 전까지 자신이 만든 예약의 목적지와 도착 목표시각을 수정할 수 있다.
- 환자의 탑승 확인 전까지 자신이 만든 예약을 취소할 수 있다.
- 예약 환자가 승차 지점에 나타나지 않거나 도착 목표시각 지연이 예상되면 알림을 받는다.
- 승객 운행 중 도움 요청이 발생하면 알림을 받고 상황을 확인한다.
- 환자의 QR이 배정된 미션과 일치하지 않으면 즉시 알림을 받는다.
- 자동 하차 확인과 환자 버튼으로도 하차를 확정하지 못하면 의료진이 확인한다.
- 가상 환자 ID를 사용하며 실제 병원 개인정보는 사용하지 않는다.
- 실제 병원 EMR·HIS와 연동하지 않는다.

## 대회 시험 대역

- 실제 환자 대신 영유아보다 조금 작은 인형을 사용한다.
- 인형 탑승, 고정 모형 QR과 하차 확인은 미션 흐름을 검증하기 위한 대역이며 승객 안전 검증 수단이 아니다.

## 관제 사용자

미션, 목적지, 의미적 위치, 진행 상태와 정지 이유를 확인한다. 정밀한 실시간 좌표는 필수로 요구하지 않으며 `승차 지점으로 이동 중`, `탑승 대기`, `목적지 이동 중`, `대체 이동 판단 중`, `대체 경로 이동 중`, `이동 불가`처럼 이해하기 쉬운 표현을 사용한다.
