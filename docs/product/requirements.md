# 요구사항

> 아래 MUST·SHOULD에는 개인 브레인스토밍으로 구체화한 운영 정책이 포함돼 있다. 팀 합의 전에는 확정 요구사항이나 구현 지시가 아니며, 현재 단계의 우선 기준은 [프로젝트 큰 틀 기준선](big-picture.md)이다.

## MUST 후보 — 팀 합의 전

- 실제로 움직이는 한 대의 축소형 자율주행 휠체어를 제작한다.
- 실제 사람을 태우지 않고 인형만 사용한다.
- 실제 서비스의 의료진 예약과 환자 직접 호출은 모두 스스로 승하차할 수 있는 비응급 환자를 대상으로 한다.
- 의료진 예약과 환자 직접 호출이라는 두 요청 진입점을 제공한다.
- 두 요청은 동일한 미션 ID와 상태 모델을 사용한다.
- 의료진 예약 시간은 출발시각이 아니라 목적지 도착 목표시각으로 입력한다.
- 의료진은 환자의 탑승 확인 전까지 자신이 만든 예약의 목적지와 도착 목표시각을 수정할 수 있다.
- 의료진은 환자의 탑승 확인 전까지 자신이 만든 예약을 취소할 수 있다.
- 미시작 예약과 직접 호출이 충돌하면 의료진 예약을 기본 우선 처리하고, 의료진은 필요하면 미시작 요청의 순서를 바꿀 수 있다. QR 탑승 확인 뒤 시작된 승객 운행은 중단하지 않는다.
- 한 번에 활성 미션은 하나만 허용하며 QR 탑승 확인 뒤의 승객 운행은 재배정하지 않는다.
- 바로 처리하지 못하는 요청은 대기열에 등록하고 대기 순번과 예상 대기시간을 표시한다.
- 환자는 휠체어가 승차 지점으로 이동 중이더라도 QR 탑승 확인 전까지 자신의 요청을 취소할 수 있다.
- 실제 서비스의 환자 직접 호출은 개인 스마트폰 웹을 목표로 한다.
- 대회 MVP의 환자 직접 호출은 승차장 태블릿·키오스크로 제공한다.
- 등록된 승차 지점과 목적지를 사용한다.
- 빈 휠체어가 대기 위치에서 승차 지점까지 이동한다.
- 대회 MVP에서는 고정된 모형 QR로 대상 미션 확인 흐름을 보여주며, 확인 전에는 목적지 운행을 시작하지 않는다.
- 의료진 예약의 환자가 승차 지점에 없으면 의료진에게 보고한 뒤 대기 위치로 자동 복귀한다.
- 승차장 직접 호출의 환자가 없으면 기본 3분 동안 기다리고 소리로 알린 뒤, 계속 나타나지 않으면 대기 위치로 자동 복귀한다. 대회 시연에서는 10초로 축약한다.
- 목적지 도착 목표시각 지연이 예상되면 의료진에게 알리고 운행은 계속한다.
- 사전에 주어진 병원 지도를 사용한다.
- 시연 공간은 선택한 장애물 대응 방식이 실제로 드러나도록 구성한다.
- 로봇은 목적지까지의 진행 상태를 판단할 수 있어야 한다.
- 장애물을 감지하면 다른 이동을 결정하기 전에 먼저 정지한다.
- 움직이는 사람도 장애물 상황으로 처리하며 먼저 정지한 뒤 허용된 장애 대응 흐름을 적용한다.
- 기존 경로가 막히면 전체 대체 경로 선택 또는 현재 경로의 제한적 수정 중 최소 하나를 이용해 안전한 이동 방법을 찾고 같은 미션을 계속한다.
- 안전한 대체 이동 방법을 찾지 못하면 `BLOCKED` 상태로 정지하고 이유를 표시한다.
- 목적지 운행이 끝난 빈 휠체어는 대기 위치로 자동 복귀한다.
- 목적지 하차 완료는 센서 자동 확인을 우선하고, 불확실하면 환자 버튼, 그래도 확인할 수 없으면 의료진 확인을 사용한다.
- 승객 운행 중 환자가 `정지·도움 요청`을 누르면 즉시 정지하고 현장 알림음과 화면으로 상태를 표시하며 등록된 담당 의료진·담당 병동 알림 대상의 화면에 알린다.
- 도움 요청 뒤에는 의료진이 상황을 확인하기 전까지 자동 재출발하지 않는다.
- 환자 화면에는 배정 여부, 예상 도착시간, 운행 상태, 탑승 확인 전 취소, 도움 요청, 병원 지도의 예정 경로와 의미적 위치를 표시한다.
- 의료진의 충돌 요청 순서 선택 목록에는 기본적으로 환자 ID와 목적지를 표시한다.
- 실제 서비스에서는 예약 환자의 병원 팔찌·환자 QR과 직접 호출 환자의 앱 QR을 사용하고, 대회 MVP에서는 고정된 모형 QR을 사용한다.
- QR이 현재 미션과 한 번이라도 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 즉시 알린다.
- QR 탑승 확인 전에 환자 요청이나 의료진 예약이 취소돼 빈 휠체어가 이동 중이면, 처리할 다음 요청이 있을 경우 해당 승차 지점으로 재배정하고 없으면 대기 위치로 복귀한다.
- 새 미션을 출발하기 전에 배터리가 운행 가능한 상태인지 판단한다.
- 운행 중 일반 저전력이 확인되면 현재 승객 운행을 완료한 뒤 대기 위치로 복귀하고 새 미션을 받지 않는다.
- 즉시 운행을 계속할 수 없는 임계 전원 문제는 일반 저전력 정책과 구분해 안전정지한다.
- 물리 비상정지는 웹·서버·상위 애플리케이션보다 우선해 모터 구동 허가를 차단한다.
- 통신 끊김과 경로 상실 시 정지하며 자동 재출발하지 않는다.
- 관제에는 미션 ID, 목적지, 의미적 위치, 진행 상태와 정지 이유를 표시하고 정밀 실시간 좌표는 필수로 요구하지 않는다.
- 호출부터 운행 종료와 실패 로그까지 종단 흐름을 시연한다.
- 정상 종단 운행, 장애 구간 대체 경로 성공, 대체 경로 없음의 안전정지를 반복 시험하고 조건·결과·로그를 남긴다.

반복 횟수는 대회 공식 요구가 아니라 내부 완성도 기준이다.

## SHOULD 후보 — 팀 합의 전

- 최종 시연에서 선택 가능한 두 번째 목적지
- 전체 대체 경로 선택과 제한적 현재 경로 수정을 모두 시연
- 카메라 기반 장애물 종류 표시 또는 기록
- 구간 진행률 표시
- 설치 가능한 PWA

## 대회 MVP 제외·장기 확장

- 미지 환경의 지도를 생성하며 이동하는 범용 자율주행
- 움직이는 사람 사이를 예측해 통과하는 동적 회피
- 사전에 허용되지 않은 공간의 임의 탐색
- 실제 환자 탑승 또는 성인 크기 시제품
- 실제 EMR·HIS·EHR와 개인정보 연동
- 복수 휠체어 배차 최적화
- 정밀 연속 좌표 관제
- 얼굴·음성 기반 환자 자동 식별
- 실제 생체신호 측정·위급 판단과 건강관리 모듈 연동
- 청소·충전·정비의 전체 운영 상태 관리와 운영자 권한 화면
- 클라우드 연결이 없으면 동작하지 않는 구조

## 아직 결정할 요구사항

- 최종 시연에서 전체 대체 경로 선택과 제한적 현재 경로 수정 중 무엇을 구현할지, 또는 둘 다 구현할지
- 병원 지도와 로봇의 진행 상태를 어떤 수준으로 표현할지
- 대체 이동 판단을 로봇 내부와 서버 중 어디에서 담당할지
- 예상 대기시간 산정 정책과 의미적 위치의 화면 갱신 수준
- 실제 병원 QR 연동과 담당 의료진 알림 전달 방식
- 목적지 도착 목표시각, 현재 시각, 운행시간과 장기 대기를 반영하는 세부 우선순위·출발시각 산정 방식
- 환자별 화면·음성 접근성 설정과 실제 서비스 운영정보의 권한별 노출 방식

지도 표현, 위치 추정, 경로 계산 알고리즘, 센서 조합과 제어 방식은 프로젝트 기획과 큰 시스템 구성이 확정된 뒤 기술 설계에서 결정한다.
