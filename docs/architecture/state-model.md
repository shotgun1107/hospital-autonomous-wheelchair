# 서비스 상태 흐름 초안

이 문서는 사용자 흐름을 확인하기 위한 상위 수준 초안이다. 내부 enum, 오류 코드, 주행 상태 머신과 전이 조건은 기술 설계에서 나중에 정한다.

## 정상 흐름

```text
요청 접수
→ 즉시 처리 또는 대기열 등록·예상 대기시간 표시
→ [의료진 예약이면 탑승 확인 전] 목적지·도착 목표시각 수정 가능
→ [탑승 확인 전이면] 환자 직접 호출 또는 의료진 예약 취소 가능
→ 미시작 요청 충돌 시 의료진 예약 기본 우선
→ 필요 시 의료진의 미시작 요청 순서 변경
→ 휠체어 배정
→ 승차 지점으로 이동
→ 탑승 대기
→ 고정 모형 QR로 미션 확인(MVP)
→ [QR 불일치 시] 목적지 운행 금지·담당 의료진 알림
→ 목적지로 이동
→ [환자 도움 요청 시] 즉시 정지·의료진 알림·확인 대기
→ 하차 대기
→ 센서 자동 확인 또는 환자 버튼·의료진 확인
→ 승객 운행 완료
→ 대기 위치 자동 복귀
```

의료진 예약과 환자 직접 호출은 같은 흐름을 사용하되 요청 출처만 구분한다. 의료진 예약은 목적지 도착 목표시각을 기준으로 하고, 대회 중심 시연은 환자 직접 호출로 구성한다.

## 환자 부재와 지연

```text
의료진 예약 환자 부재
→ 의료진 보고
→ 요청 종료
→ 대기 위치 복귀

승차장 직접 호출 환자 부재
→ 기본 3분 대기(대회 시연 10초)
→ 소리 알림
→ 계속 부재 시 요청 종료
→ 대기 위치 복귀

도착 목표시각 지연 예상
→ 의료진 알림
→ 운행 계속
```

## 탑승 전 취소와 빈 차량

```text
탑승 확인 전 환자 직접 호출 또는 의료진 예약 취소
→ 승객 없는 상태 확인
→ 다음 요청 있음: 해당 승차 지점으로 재배정
→ 다음 요청 없음: 대기 위치 복귀
```

## 배터리

```text
새 미션 출발 전 배터리 확인
→ 출발 조건 미달: 미션 시작 금지

승객 운행 중 일반 저전력
→ 현재 목적지 운행 완료
→ 하차 확인
→ 새 미션 금지
→ 대기 위치 복귀

임계 전원 문제
→ 안전정지
```

## 장애물 발생 흐름

```text
이동 중 장애물 발견
→ 먼저 정지
→ 기존 요청과 목적지 유지
→ 안전한 대체 이동 방법 판단
→ 가능하면 같은 요청 계속
→ 불가능하면 이동 불가 상태 표시와 사람 개입 요청
```

대체 이동 판단 중에도 안전 계층이 이동을 허용하지 않으면 움직이지 않는다.
움직이는 사람도 이 장애물 흐름에 포함한다.

## 승객의 정지·도움 요청

```text
승객 운행 중 도움 요청
→ 즉시 정지
→ 현장 알림음·화면 표시
→ 담당 의료진 알림
→ 의료진 확인 전 자동 재출발 금지
```

## 기타 실패 흐름

경로를 잃거나 통신·전원·센서·비상정지 문제가 발생하면 안전하게 정지한다. 복구할 수 없으면 요청을 중단하고 사람이 모형을 회수한다.

## 현재 단계의 불변 원칙

- 한 대의 휠체어에는 동시에 하나의 활성 이동만 둔다.
- 의료진 예약의 기본 우선은 미시작 요청에만 적용하고 탑승 뒤 승객 운행을 중단하지 않는다.
- QR로 대상 미션을 확인하기 전에는 목적지 운행을 시작하지 않는다.
- QR이 현재 미션과 일치하지 않으면 목적지 운행을 시작하지 않고 담당 의료진에게 알린다.
- 하차 완료가 확인되기 전에는 자동 복귀를 시작하지 않는다.
- 도움 요청 뒤에는 의료진 확인 전 자동 재출발하지 않는다.
- 새 미션 출발 조건에는 배터리 상태가 포함된다.
- 안전 계층의 정지를 웹이나 서버가 강제로 해제할 수 없다.
- 완료·취소·중단된 요청은 새 확인 없이 다시 실행하지 않는다.
- 청소·충전·정비 운영 상태 관리는 대회 MVP에서 다루지 않되 새 미션 출발 전 배터리 조건 확인은 유지한다.

정확한 상태 이름, 내부 상태 수, 전이 이벤트와 자동 재개 조건은 큰 시스템 구성과 안전 정책이 합의된 뒤 결정한다.
