# 주행과 지도 개념 초안

이 문서는 기술 설계가 아니라 큰 시스템 구성을 논의하기 위한 초안이다. 지도 데이터 형식, 위치 추정, 경로 계산 알고리즘, 센서와 제어 방식은 확정하지 않는다.

## 현재 합의된 기능 의도

- 병원 지도가 사전에 제공된다고 가정한다.
- 대기 위치, 등록된 승차 지점과 목적지 사이를 자동으로 이동한다.
- 로봇 또는 시스템은 현재 미션의 진행 상태를 판단할 수 있어야 한다.
- 진행 경로가 장애물로 막히면 먼저 정지한다.
- 전체 대체 경로 선택 또는 제한적 현재 경로 수정으로 안전한 이동 방법을 찾으면 같은 미션을 계속한다.
- 대체 이동 방법이 없으면 `BLOCKED`로 정지하고 이유를 표시한다.
- 두 방식 중 무엇을 MVP로 구현할지 또는 둘 다 구현할지는 아직 정하지 않는다.

## 관제에 필요한 정보

관제 사용자는 정밀 좌표보다 다음 정보를 우선 확인한다.

- 현재 미션과 목적지
- 대기 위치·승차 지점·목적지 이동 중 같은 의미적 위치
- 정상 이동, 탑승 대기, 장애물 정지, 대체 이동 중, 이동 불가 같은 진행 상태
- 정지 또는 실패 이유

로봇 내부에서 더 세밀한 위치 정보가 필요한지는 이후 기술 설계에서 판단한다.

## 큰 구성에서 먼저 결정할 사항

- 병원 지도를 누가 생성·관리하고 로봇에 전달하는가?
- 대체 이동 판단을 로봇 내부와 서버 중 어디에서 담당하는가?
- 로봇은 서버 연결 없이 어느 범위까지 이동과 장애 대응을 계속할 수 있는가?
- 지도에는 장소, 통로, 이동 금지 구역과 대체 경로 중 무엇이 포함돼야 하는가?
- 전체 대체 경로 선택과 제한적 현재 경로 수정 중 무엇을 MVP에 포함할 것인가?

## 아직 선택하지 않는 기술

- 지도와 경로의 구체적인 데이터 구조
- 현재 위치와 진행량을 추정하는 방법
- 대체 경로 및 국소 경로 수정 알고리즘
- 전달된 Arduino·초음파 방향의 정확한 모델·개수·배치와, 표식·바퀴 센서를 포함한 최종 조합
- 내부 주행 상태, 메시지 필드와 안전 임계값

앞서 검토된 기술 후보는 [장애물 대응 기술 후보 메모](../research/technology/obstacle-routing-options.md)에 분리해 두며, 아직 채택된 설계로 보지 않는다.
