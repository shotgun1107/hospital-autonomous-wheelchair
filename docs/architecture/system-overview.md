# 시스템 개요

현재 문서는 큰 구성 논의를 위한 초안이며 최종 아키텍처가 아니다.

현재 시스템은 다음 책임 계층으로 구분한다.

1. 실제 서비스용 환자 스마트폰 웹, 대회용 승차장 태블릿·키오스크와 의료진 화면을 포함하며 지도·의미적 위치, 도움 요청과 하차 확인의 수동 보완을 제공하는 사용자 인터페이스 영역
2. 목적지 도착 목표시각 예약과 탑승 확인 전 수정·취소, 직접 호출, 대기열·대기 순번·예상 대기시간, 미시작 요청의 의료진 예약 기본 우선과 의료진 순서 변경, 도움 요청의 의료진 알림, 탑승 전 취소·빈 차량 재배정, 하차 확인과 배터리 조건에 따른 미션 흐름·이력을 관리하는 서버
3. 이동 목표를 수행하고 장애 상황을 처리하며 승객의 정지·도움 요청에 따라 정지하는 로봇 자율주행 영역
4. 자동 하차 확인과 배터리 상태를 포함한 센서 입력 및 모터를 다루는 임베디드 제어 영역
5. 위험 시 실제 구동을 멈추고 임계 전원 문제에 대응하는 하드웨어 안전 영역
6. 사전에 주어진 병원 지도와 영역 간 계약

로봇 자율주행과 임베디드 제어를 같은 보드에 둘지 분리할지는 아직 결정하지 않는다.

## 핵심 원칙

- 서버는 미션을 배정하지만 로컬 안전 정지를 해제할 수 없다.
- 도움 요청으로 정지한 승객 운행은 의료진 확인 전 자동 재출발하지 않는다.
- 의료진 예약의 기본 우선은 미시작 요청에만 적용하며 이미 탑승해 이동 중인 승객 운행을 중단하지 않는다.
- 로봇의 실제 진행 상태는 로봇 측에서 확인할 수 있어야 한다.
- 장애물 대응의 첫 동작인 정지는 서버 왕복을 기다리지 않아야 한다.
- 대체 이동 판단을 서버와 로봇 중 어디에서 수행할지는 아직 결정하지 않는다.
- 임베디드와 하드웨어 안전 영역은 상위 통신이 없어도 정지할 수 있어야 한다.
- 관제에는 정밀 좌표를 필수로 요구하지 않고 미션, 목적지, 의미적 위치, 진행 상태와 정지 이유를 표시한다.
- 하드웨어 없이 웹·서버 흐름을 확인할 대체 수단이 필요한지는 큰 구성에서 결정한다.
