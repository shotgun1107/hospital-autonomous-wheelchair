# 책임 경계 초안

이 문서는 큰 시스템 구성을 논의하기 위한 후보이며 최종 기술 배치를 확정하지 않는다.

| 큰 영역 | 상위 책임 |
| --- | --- |
| 사용자 화면 | 환자·의료진 요청 입력, 의료진 예약의 탑승 확인 전 수정·취소, 환자의 QR 확인 전 취소·도움 요청, 예정 경로·의미적 위치 표시, 환자 버튼·의료진 하차 확인, 의료진의 미시작 요청 순서 변경·부재·도움 요청 확인과 진행 상태 표시 |
| 운영 서버 | 목적지 도착 목표시각 예약·탑승 확인 전 수정·취소·직접 호출, 대기열·대기 순번·예상 대기시간, 미시작 요청의 의료진 예약 기본 우선, 환자별 담당 의료진·병동 알림 대상 연결, 부재·지연·도움 요청·QR 불일치 알림, 빈 차량 재배정, 하차 확인·배터리 조건에 따른 미션 흐름과 운행 이력 관리 |
| 로봇 자율주행부 | 주어진 이동 목표 수행, 진행 상태 판단, 장애 상황 보고와 승객 도움 요청 시 정지 |
| 임베디드 제어부 | 실제 구동부와 센서 제어, 자동 하차·배터리 상태 입력, 상위 명령을 물리 동작으로 변환 |
| 하드웨어 안전부 | 비상정지, 임계 전원 문제와 위험 시 구동 차단 |
| 현장 운영자 | 탑승 확인, 필요 시 하차 확인, 재개 판단과 수동 회수 |

## 우선 원칙

```text
물리 안전
> 로컬 정지 판단
> 이동 목표와 운영 명령
> 사용자 요청
```

상위 계층은 하위 안전 계층의 정지를 강제로 해제할 수 없다.

## 큰 구성에서 남은 질문

- 대체 이동 판단을 운영 서버와 로봇 자율주행부 중 어디에서 담당할 것인가?
- 서버 연결이 끊겨도 로봇이 현재 이동을 어느 범위까지 처리할 것인가?
- 임베디드 제어부와 자율주행부를 한 보드에 둘지 분리할 것인가?
- 어떤 상태를 서버의 기록으로 보고 어떤 상태를 로봇의 실제 상태로 볼 것인가?

명령 필드, 순번, 시간 제한, 통신 주기와 내부 권한 검증 방식은 기술 설계 단계에서 정한다.
