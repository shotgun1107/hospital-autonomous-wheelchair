# 데이터 흐름 초안

이 문서는 기능 영역 사이의 상위 흐름만 정의한다. 메시지 형식, 통신 방식과 내부 처리 알고리즘은 확정하지 않는다.

## 의료진 예약

의료진 화면 → 가상 환자·목적지 도착 목표시각·승차 지점·목적지 입력 → 운영 서버의 이동 요청 생성 → 탑승 확인 전 필요 시 목적지·도착 목표시각 수정 또는 예약 취소 → 미시작 요청 충돌 시 의료진 예약 기본 우선 → 필요 시 의료진이 환자 ID·목적지 목록에서 순서 변경 → 배정 또는 대기열 → 로봇에 이동 목표 전달 → 실제 운행 상태 반환 → 화면 표시

## 환자 직접 호출

개인 스마트폰 웹 또는 대회용 승차장 태블릿·키오스크 → 목적지 선택 → 운영 서버의 즉시 처리 또는 대기열 등록 → 대기 순번·예상 대기시간 표시 → QR 탑승 확인 전 환자 취소 또는 이동 차례 도달 → 이동 차례가 되면 같은 이동 흐름 사용

환자 화면에는 배정 여부, 예상 도착시간, 운행 상태, 도움 요청과 병원 지도의 예정 경로·의미적 위치를 함께 표시한다.

## 탑승 확인과 자동 복귀

휠체어의 승차 지점 도착 → 고정 모형 QR로 대상 미션 확인(MVP) → 일치: 목적지 운행 / 불일치: 운행 금지·담당 의료진 알림 → 목적지 운행 → 센서 자동 하차 확인 → 불확실하면 환자 버튼 → 필요하면 의료진 확인 → 승객 운행 종료 → 빈 휠체어의 대기 위치 복귀

## 탑승 전 취소와 빈 차량 재배정

탑승 확인 전 환자 직접 호출 또는 의료진 예약 취소 → 승객 없는 휠체어 → 다음 요청 있음: 해당 승차 지점 재배정 / 다음 요청 없음: 대기 위치 복귀

## 환자 부재와 도착 지연

- 의료진 예약 환자 부재 → 의료진 보고 → 요청 종료와 자동 복귀
- 승차장 직접 호출 환자 부재 → 기본 3분 대기(대회 시연 10초) → 소리 알림 → 계속 부재 시 요청 종료와 자동 복귀
- 목적지 도착 목표시각 지연 예상 → 의료진 알림 → 운행 계속

## 정상 주행

사전에 주어진 병원 지도와 이동 목표 → 로봇 자율주행부 → 임베디드 제어부 → 구동부 → 진행 상태 반환

## 장애물 대응

고정 장애물 또는 움직이는 사람 발견 → 로컬 정지 → 대체 이동 가능 여부 판단 → 가능하면 같은 요청 계속 → 불가능하면 정지 상태와 이유 보고

정지 자체는 서버 응답을 기다리지 않아야 한다. 대체 이동을 어느 영역에서 판단할지는 아직 결정하지 않았다.

## 승객의 정지·도움 요청

환자 화면의 도움 요청 → 즉시 정지 → 현장 알림음·화면 표시 → 운영 서버에 상태 보고 → 환자 정보에 등록된 담당 의료진·담당 병동 알림 대상의 화면에 알림 → 의료진 확인 전 자동 재출발 금지

건강관리 모듈 또는 기존 환자 모니터링 시스템의 자동 위급 신호 연동은 장기 아이디어이며 대회 MVP 활성 흐름에 포함하지 않는다.

## 안전과 실패

비상정지, 경로 상실, 통신 문제 또는 기타 위험 → 로컬 정지 → 상태 보고 → 운영 화면 표시 → 필요 시 현장 회수

## 배터리

- 새 미션 출발 전 배터리 확인 → 출발 조건 미달 시 미션 시작 금지
- 승객 운행 중 일반 저전력 → 현재 운행 완료 → 하차 확인 → 새 미션 금지 → 대기 위치 복귀
- 임계 전원 문제 → 안전정지

세부 API와 로봇 통신 계약은 큰 책임 경계가 확정된 뒤 `contracts/`에서 정의한다.
